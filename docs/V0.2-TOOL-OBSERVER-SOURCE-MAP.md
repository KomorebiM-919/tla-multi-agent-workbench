## Seam supported by evidence

`tools/result` is delivered after tool materialization and retains the exec
identity and final structured value on success. `scopeTarget` permits an
unscoped listener through the agent scope filter. The foreground-pwsh DTO can
carry `cwd`, `exitCode`, `signal`, timeout/abort and stdout/stderr truncation
facts.

This supports a same-process passive candidate. It does **not** prove live
member composition, fork seed replay, out-of-process child coverage, lossless
delivery, or a total physical order.

## Host-shaped adapter

`orchestration/tool-observer/host-bridge.mjs` is a separate, opt-in projection
and bridge. It is not a change to the generic `mapToolsResult` adapter.

- `tools/result` uses positional `(exec, result)`; `session/event` uses
  `(session, event)`. The caller injects
  `subscribe(eventName, callback) -> disposeFunction`.
- The bridge reads only the fields in the table above. It never imports a DSH
  module, discovers a dispatcher, subscribes on import, or reads credentials,
  prompt text, tool arguments, stdout/stderr text, cwd or file content.
- Missing/invalid identities become `null`; a bounded `FIELD_UNAVAILABLE` or
  `FIELD_INVALID` diagnostic is recorded. Known process facts are compared by the
  existing cross-source rules; `null` remains unknown, not "different".
- Registration failure rolls back prior valid disposers. If a `subscribe` call
  retained a callback but threw or returned no disposer, the bridge latches
  stopped so the callback is inert and reports `ownershipUncertain: true`; it
  does not pretend detachment was proven.
- Only `origin: simulated-dispatcher` is accepted. The `host-notification`
  origin is reserved for a future actually attached context and is not produced
  by this adapter. A matching receipt or a host-shaped test object cannot turn
  invented data into runtime evidence.

## Subscription API

The audited source shows a dispatcher-shaped seam but does not establish a
stable public Node API for this package. The generic adapter therefore accepts
an injected dispatcher with `on`/`off`, and an explicit `subscriptions` list. The
host-shaped bridge separately accepts the injected
`subscribe(eventName, callback) -> disposeFunction` boundary. Neither adapter
imports DSH, auto-discovers a dispatcher, installs a plugin, or subscribes on
import.

The default subscription set of the generic adapter is `['tools/result']`.
`session/event` is available only when the caller supplies a mapper and a
dispatcher that exposes that event. The host-shaped bridge defaults to both
audited event names and requires the caller's `subscribe` implementation. If
the actual host API or field names differ, the correct result is an unsupported
adapter path or a recorded diagnostic, not a guessed API.

An actual Cordis/DSH context wrapper and its `off`/dispose contract remain
**unsupported** until independently sourced and reviewed. The bridge's
`subscribe -> dispose` signature is an explicit test/project boundary, not a
claim that DSH exposes it.

What this supports: a thin, explicit `ctx.on(event, callback)` registration whose
returned function is the disposer; the method must be called with `ctx` as
receiver; no `ctx.off` is required. What it does **not** prove: a stable public
export, member coverage, lossless delivery, or that a particular host context is
available to an installed plugin. `ctx.on` can return a non-function in a
special internal-listener path, so the adapter validates the return value rather
than assuming a disposer.

`orchestration/tool-observer/context-subscription.mjs` is this boundary. It
accepts an explicit `ctx`, calls `ctx.on(name, callback)` as a method with
exactly two arguments, rejects a non-function return, never calls `ctx.off`, and
never sets `global`/`prepend`. Import has no side effects and no context is
discovered. The bridge still accepts only `origin: simulated-dispatcher`.

### Disposal timing

A Cordis disposer may return a thenable. The bridge's `stop()` is synchronous:
it counts each async disposer separately, so one resolution cannot clear the
aggregate pending state while another disposer is still outstanding. If any
disposer is pending, it reports `ok:false`, `ownershipUncertain:true` and
`asyncCleanupPending:true` instead of claiming cleanup. It attaches a rejection
handler to avoid an unhandled rejection and updates the returned health object to
`asyncCleanupSettled:true` when all observed disposers settle; a failure is
latched in `asyncCleanupFailure` and is not erased by a later success. The same
aggregate state is used for registration-failure rollback, so a rollback does
not remain `pending` after all its async disposers settle. It does not add an
asynchronous close contract. A fully resolved async cleanup also leaves
`ok:false`, because the synchronous call did not wait for and independently
confirm the transition; `ownershipUncertain` becomes false once no outstanding
or failed item remains.

## Limits

- Source support is scoped to the audited entries; the archive is not a running
  Desktop process and no publisher signature is claimed.
- Delivery order is observer order, not physical execution order.
- Unknown identity remains null plus a diagnostic; no role, task, attempt or
  path is inferred from tool names.
- `hostVerified=false`, `coverage=unknown`, `binding=unproven` in every trace and
  report. This package does not install the observer or authorize a host run.
