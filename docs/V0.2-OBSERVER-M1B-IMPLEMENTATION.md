## Supervised spec and gate wiring

`spec.observer` is absent by default. When present it is a strict
`tla.observer-plan/v1` object:

```text
schema, plugin, packageRoot, version, fileCount, digest,
limits {maxBytes, maxObservations, maxPending}, cleanupTimeoutMs
```

It requires `evidenceReceipts=true` and the standard gated launcher. A custom
`hostCommand` is refused because it cannot produce the two B0 receipts.

The runner writes `runDir/observer-plan.json`; the gate is the only component
that renders the observer patch. After its actual `gateRunId` exists and the
runner's `runnerRunId`/`launchId` are available, the gate writes:

```text
runDir/observer-launch.patch.yml
runDir/observer/                  fresh empty plugin runDir
```

The 12 config fields are `enabled`, `runDir`, `traceFile`, `lifecycleFile`,
`runnerRunId`, `launchId`, `gateRunId`, `budgetRunId`, `maxBytes`,
`maxObservations`, `maxPending`, `cleanupTimeoutMs`. `gateRunId === budgetRunId`.
The upstream service run ID is never used as a gate ID. The probe and host use
the same patch list; `--dump-config` is only a synthesis check.

## Mount-probe checker

`tools/check-observer-mount-probe.mjs --input <json>` evaluates synthetic
evidence and emits `tla.observer-mount-probe/v1` with:

- `scope=mount-probe`;
- `status=probe-passed|incomplete|failed`;
- `hostVerified=false`, `coverage=unknown`;
- `binding` only `consistent` from B0 or `unproven`;
- `closed=false`.

It requires the lifecycle journal preparing/attached/stopping/stopped, a
non-degraded `host-notification` trace, read and foreground pwsh results, no
unexpected tools, both receipts, complete ledger and clean observer cleanup.
Missing evidence is `incomplete`; contradictory evidence is `failed`; it never
claims business closure or real host coverage.

## What is still unproven

No real subscription, member/tool coverage, DTO shape, mount or stop was
observed. The package is not installed, the mount probe uses synthetic records,
and the B0 receipts are local correlation evidence, not authentication. A future

The host-descendant evidence problem is **not** solved by the runtime watcher

journal; it is not authorization to start a real experiment.

### Correction round 2: single-defect negatives

A receipt pair can join (`binding=consistent`) while the rest of the mount
evidence is wrong. The probe now also requires:

- journal `launchId` == runner receipt `launchId` == trace binding claim;
- gate summary `hostStarted=true` (missing is incomplete, false is failed);
- runner summary `status=completed` (missing is incomplete, another status is
  failed);
- an empty ledger `upstreamOverGate` array, even when `complete=true`;
- per-record budget identity, including `runId`/`budgetRunId` alias conflicts;
  invalid records are not dropped.

These are separate checks; the five single-defect fixtures each return
`failed` even when the receipt pair is `local-runtime` and `binding=consistent`.
A complete `local-runtime` fixture can be `probe-passed`, but remains
`hostVerified=false`, `coverage=unknown`, `closed=false`; `local-runtime` is
still invented data, not a real launch receipt.

### Correction round 3: success is more than `hostStarted`/`completed`

The gate's `hostStarted=true` is not a protection success. The probe now also
requires gate `result=host-ok`, `decision.allow=true`, an empty
`decision.blockers` array and `exitCode=0`. A refused gate
(`protection-not-established`, `allow=false`, `HEARTBEAT_MISSING`) is `failed`.

The runner's `completed` status does not override teardown evidence. The probe
requires host, upstream and ports teardown records; host/upstream `survivors`
must be empty arrays and `how` must be `already-exited` or `tree-killed`; the
ports record must report both ports free. Missing records are `incomplete`,
survivors or a held port are `failed`.

For foreground pwsh, all six process facts must agree: `exitCode=0`,
`signal=null`, `timedOut=false`, `aborted=false`, and both truncation flags
false. An exit 0 paired with `SIGTERM` is `failed`. The B0 binding only records
receipt association; it does not turn any of these checks into host coverage.


### Correction round 4: complete, unambiguous teardown evidence

The previous round's teardown description was stricter than the producer for
normal process termination, but did not actually require the upstream record.
The mount probe now requires exactly one host, one upstream and one ports
record. Missing roles are incomplete; repeated roles are failed even when
identical. Every record is inspected, including both sides of duplicate roles,
so a first successful ports entry cannot hide a later held port. Unknown roles
or malformed entries make the material incomplete rather than disappearing.

For host and upstream, stopOwnedProcess's successful outcomes are
`already-exited`, `terminated`, `tree-killed` and `killed`, with an empty
array of survivors. `still-alive` and `descendants-survived` are failed;
`none`, missing or unknown outcomes are incomplete. Port-free facts must both
be boolean true. A failure in any entry takes precedence over incomplete
evidence elsewhere. No new report fields, B0 meanings or producer behavior
are introduced. These cleanup outcomes do not establish descendant coverage
or authenticate historical process/port observations.

The 67-case M1B suite includes independent role deletions, duplicate records
in both orders, identical duplicates, all four successful outcomes for both
process roles, malformed records and fields, and a real local child stopped
by the existing producer. That child is a Node stand-in, not DSH; the rest
of its mount materials remain synthetic. No installation, real-host run or
coverage claim is added.

### Correction round 5: host descendants must not remain unknown

Round 4 accepted already-exited for both roles without requiring the host's
descendant evidence. Independent review showed that this could probe-pass
even when treeProof was exited-before-teardown, or the host's
descendantsProof was unavailable. The earlier 67-case result was real, but
its host/already-exited positive encoded an insufficient evidence rule.

The mount probe now separates host from upstream. A host needs:

- a successful terminated/tree-killed/killed outcome and no survivors;
- descendantsProof=collected, with a unique array of positive safe-integer
  descendant pids (an empty collected snapshot is valid);
- runner treeProof=tree-killed for an empty snapshot, or descendants-killed
  for a non-empty snapshot. A contradiction between known claims is failed.

Already-exited, exited-before-teardown, descendants-unverified, missing or
malformed snapshot/proof information is incomplete, not successful cleanup.
An explicit surviving process still makes the result failed even when other
evidence is missing. The single-process upstream may still be already-exited
and may retain descendantsProof=skipped; its result cannot stand in for host
proof. These are finite snapshot observations, not authentication or a claim
that no process can escape, detach or appear after enumeration.

The runner preserves unavailable enumeration as treeProof=descendants-unverified
instead of folding it into tree-killed. Collected evidence accompanied by a
failed cleanup is cleanup-failed. requireTreeProof=true only allows completed
when treeProof is tree-killed or descendants-killed; otherwise a previously
completed run becomes cleanup-anomaly. Existing timeout/cancel/receipt failures
are not replaced. With requireTreeProof omitted/false the runner may retain
completed with unverified evidence, but the mount probe still refuses it. No
CLI option, dependency or configuration field was added. Consumers must handle
the new conservative summary values rather than treating unknown values as
success. Historical handoff manifests and reports have not been rewritten.

The 95-case M1B suite includes both review counterexamples, snapshot/proof
boundaries, matching/mismatching collected snapshots, role separation and
CLI incomplete exit 1. The runner suite has 131 checks. Its new deterministic
test blocks only the process-table query and clears a local stand-in child's
exitCode after its real exit event to exercise the teardown-result race. This
is test-only instrumentation, not a production hook or evidence of real DSH
behavior. Both relaxed and strict requireTreeProof modes are checked, along
with dead owned pids, released ports and unchanged primary failure semantics.

A normally self-exiting real host can therefore leave the mount probe
incomplete. A future successful live proof would need independent descendant
evidence at the relevant boundary; this correction does not add that collector
or bypass the gate to make the planned experiment pass. Real installation,
member coverage, mounting and business closure remain unverified.

### Correction round 6: runtime observer watch

`docs/V0.2-OBSERVER-M1B-APPROVAL.md` section 6 requires the supervisor to allow
a **bounded attachment window** (proposed maximum 10 s, inside the overall host
timeout) and to validate the watcher identity and journal records rather than
checking file existence. The reviewed tip only rendered the observer patch: the
gate never read the journal, so an observer that never attached, attached for
another run, or died mid-run still ended as `host-ok`.

`tools/lib/observer-journal.mjs` reads the journal **prefix** with the production
rules from `orchestration/tool-observer/lifecycle.mjs` (12 exact keys, contiguous
`seq`, UUID/ID checks, `gateRunId === budgetRunId`, stable identity across
records, phase transitions, 64 KiB / 16 records / 4 KiB limits) and differs in
exactly two ways: a terminal phase is not required, and a trailing line without
its newline is dropped instead of becoming a record or a contradiction. States:
`pending`, `attached`, `stopped`, `failed`, `mismatch`, `invalid`. `origin` is
deliberately **not** compared: a `local-runtime` journal is legitimate, and
consistency is not provenance.

`tools/gated-run.mjs` now (a) waits for `attached` within
`--observer-attach-ms` (1..10000, default 10000) and never past the host
deadline, (b) re-reads the journal on each existing lease-renewal tick and
revokes on `failed`/`mismatch`/`invalid`, and (c) requires `stopped` before
declaring success. Outcomes before the lease: `observer-not-attached` (window or
host exit) and `observer-identity-failed` (mismatch/invalid/failed), both exit 3
and the host is stopped. Outcome after the lease: `observer-failed`, exit 4.
Clean host exit with a journal lacking `stopped`: `observer-incomplete`, exit 3 —
an observer failure is a failed trial even when the host exits zero. The gate
summary records `observer.patchPath`, `attachWindowMs`, `status`, `attachStatus`,
`attachWaitedMs`, `attachPolls`, `attachDetail`, `finalStatus` and `failure`.

The watcher is a test/decision path only: it starts no second host, adds no
supervisor platform, no second execution loop and no new dependency. It reads the
run directory the gate already created for the run, using the receipts the gate
already wrote.

Tests: `tests/v02-observer-watch.test.mjs` covers the prefix semantics,
torn-line tolerance, the cross-check against the envelope reader, and the bounded
wait including the exact window boundary, `host-exited`, contradiction-abort and
the deadline cap. `tests/v02-gate.test.mjs` scenario `launcher observer watch`
runs five stub-host cases (complete, unattached, foreign launchId, failed
mid-run, no terminal phase) against the real launcher, with the 12-file envelope
mounted in the isolated launcher home so the reviewed identity check is exercised
at real bytes. Self-check for round 6: watch 17/17, gate 19 scenarios / 213
checks / 0 failures, all exit 0.

### Correction round 7: loss of an attached journal, bounded stop, strict final read

Independent review found four residual gaps in round 6. First, the runtime watch
only reacted to `failed`/`mismatch`/`invalid`: a journal deleted, emptied or
regressed to `preparing` after `attached` stayed `pending`, so the lease kept
renewing; and an early `stopping`/`stopped` while the host was still running was
ignored, so the gate kept authorising model requests. Second, a detected loss did
not converge: the exit race was only against the host exit and the full host
timeout, so a run with a lost observer still waited out the whole window before
the bounded termination path ran. Third, reading the journal inside the renewal
callback could throw (for example when the path is replaced by a directory) and
escape as an uncaught exception from a timer callback. Fourth, the final
judgement used the prefix reader, so a half-written trailing line, invalid UTF-8
or a record after the terminal phase could still be recorded as success.

Behaviour now. Runtime classification is a single table,
`observerRuntimeFailure(state)`: `attached` keeps authorising; `pending` maps to
`OBSERVER_REGRESSED`; `stopped` maps to `OBSERVER_STOPPED_EARLY`; `failed`,
`mismatch` and `invalid` map to their own codes, and an unknown state maps to
`OBSERVER_INVALID`. A read error is caught in place and becomes
`OBSERVER_READ_FAILED`. Any of these revokes the lease immediately
(`gate.revoke(code)`) and resolves the same race the heartbeat loss already used,
so the existing bounded termination path runs at once instead of at the host
timeout. The new outcome is `observer-stopped-early` (exit 4); every other
runtime loss keeps `observer-failed` (exit 4), and `observer.failure` carries the
code.

Early stop versus normal teardown. The plugin writes `stopping`/`stopped` during
host shutdown, and the host exit event follows a few milliseconds later, so
terminating on the first sighting of `stopped` would mislabel ordinary cleanup as
a failure. The gate therefore stops renewing but allows a bounded grace of the
plan's own `cleanupTimeoutMs` for the host to exit by itself; if the host is
still running when that grace ends, `OBSERVER_STOPPED_EARLY` is declared. No new
time parameter is introduced: the grace reuses the value the plan already pins.

Final judgement. `awaitObserverStop` re-reads inside the same `cleanupTimeoutMs`
budget (bridge for the same race) and then decides with the envelope's strict
`readLifecycle`: complete UTF-8, no torn trailing line, no record after the
terminal phase, identity unchanged. A half line, invalid UTF-8 or a
post-terminal record is `invalid`, which stays `observer-incomplete` at exit 3 and
can never be reported as a successful trial. Only a strict, identity-matched
`stopped` journal allows `host-ok`.

The gate summary now records `observer.failure` (code or final state), `detail`,
`finalStatus`, `stopWaitedMs` and `stopPolls` in addition to the round-6 fields;
`status` keeps the last runtime observation while `finalStatus` is the closing
verdict.

Reproduction before the fix, from the same stub host: deleting, truncating or
regressing the journal after `attached` ended as `observer-incomplete` at exit 3
only after the host finished on its own, replacing the path with a directory
crashed the launcher so no summary was written at all, and the early-stop and
torn-tail cases could not even be reached. Self-check for round 7: watch 29/29,
gate 19 scenarios / 250 checks / 0 failures, `M1B ENVELOPE OK (12 files,
dc68af450872)`; the envelope bytes and the reviewed identity constants are
unchanged. This is still stub-only: no host was started, nothing was installed,
and the descendant-evidence blocker below is untouched.
