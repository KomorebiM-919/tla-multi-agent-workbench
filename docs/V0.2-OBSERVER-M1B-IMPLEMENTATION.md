## Supervised spec and gate wiring

`spec.observer` is absent by default. When present it is a strict
`tla.observer-plan/v1` object:

```text
schema, plugin, packageRoot, version, fileCount, digest,
limits {maxBytes, maxObservations, maxPending}, cleanupTimeoutMs
```

It requires `evidenceReceipts=true` and the standard gated launcher. A custom
`hostCommand` is refused because it cannot produce the two B0 receipts.

The runner writes `runDir/observer-plan.json`; the gate is the only component
that renders the observer patch. After its actual `gateRunId` exists and the
runner's `runnerRunId`/`launchId` are available, the gate writes:

```text
runDir/observer-launch.patch.yml
runDir/observer/                  fresh empty plugin runDir
```

The 12 config fields are `enabled`, `runDir`, `traceFile`, `lifecycleFile`,
`runnerRunId`, `launchId`, `gateRunId`, `budgetRunId`, `maxBytes`,
`maxObservations`, `maxPending`, `cleanupTimeoutMs`. `gateRunId === budgetRunId`.
The upstream service run ID is never used as a gate ID. The probe and host use
the same patch list; `--dump-config` is only a synthesis check.

## Mount-probe checker

`tools/check-observer-mount-probe.mjs --input <json>` evaluates synthetic
evidence and emits `tla.observer-mount-probe/v1` with:

- `scope=mount-probe`;
- `status=probe-passed|incomplete|failed`;
- `hostVerified=false`, `coverage=unknown`;
- `binding` only `consistent` from B0 or `unproven`;
- `closed=false`.

It requires the lifecycle journal preparing/attached/stopping/stopped, a
non-degraded `host-notification` trace, read and foreground pwsh results, no
unexpected tools, both receipts, complete ledger and clean observer cleanup.
Missing evidence is `incomplete`; contradictory evidence is `failed`; it never
claims business closure or real host coverage.

## Correction round

The mount-probe input is only `{schema, materials}`: journal, trace, both
receipts, runner/gate summaries, budget events and ledger are read from files.
The evaluator uses the production lifecycle reader, B1 trace contract and
receipt/ledger validators. `event=call` may come from `session/event` while
`event=result` comes from `tools/result`; pairing is by session/call/root/tool.
Missing evidence is `incomplete`, contradictions are `failed`; simulated
receipts keep `binding=unproven`.

The envelope root `package.json` is LF-pinned in `.gitattributes`, compared by
Git blob and verified in a fresh `autocrlf=true` checkout and `git archive`. The
checker assembles the exact 12-file closure and imports the entry. All 12
entries carry a recomputable blob; the historical seven-file, M0 and M1A
manifests remain frozen.

### Correction round 2: single-defect negatives

A receipt pair can join (`binding=consistent`) while the rest of the mount
evidence is wrong. The probe now also requires:

- journal `launchId` == runner receipt `launchId` == trace binding claim;
- gate summary `hostStarted=true` (missing is incomplete, false is failed);
- runner summary `status=completed` (missing is incomplete, another status is
  failed);
- an empty ledger `upstreamOverGate` array, even when `complete=true`;
- per-record budget identity, including `runId`/`budgetRunId` alias conflicts;
  invalid records are not dropped.

These are separate checks; the five single-defect fixtures each return
`failed` even when the receipt pair is `local-runtime` and `binding=consistent`.
A complete `local-runtime` fixture can be `probe-passed`, but remains
`hostVerified=false`, `coverage=unknown`, `closed=false`; `local-runtime` is
still invented data, not a real launch receipt.

### Correction round 3: success is more than `hostStarted`/`completed`

The gate's `hostStarted=true` is not a protection success. The probe now also
requires gate `result=host-ok`, `decision.allow=true`, an empty
`decision.blockers` array and `exitCode=0`. A refused gate
(`protection-not-established`, `allow=false`, `HEARTBEAT_MISSING`) is `failed`.

The runner's `completed` status does not override teardown evidence. The probe
requires host, upstream and ports teardown records; host/upstream `survivors`
must be empty arrays and `how` must be `already-exited` or `tree-killed`; the
ports record must report both ports free. Missing records are `incomplete`,
survivors or a held port are `failed`.

For foreground pwsh, all six process facts must agree: `exitCode=0`,
`signal=null`, `timedOut=false`, `aborted=false`, and both truncation flags
false. An exit 0 paired with `SIGTERM` is `failed`. The B0 binding only records
receipt association; it does not turn any of these checks into host coverage.


### Correction round 4: complete, unambiguous teardown evidence

The previous round's teardown description was stricter than the producer for
normal process termination, but did not actually require the upstream record.
The mount probe now requires exactly one host, one upstream and one ports
record. Missing roles are incomplete; repeated roles are failed even when
identical. Every record is inspected, including both sides of duplicate roles,
so a first successful ports entry cannot hide a later held port. Unknown roles
or malformed entries make the material incomplete rather than disappearing.

For host and upstream, stopOwnedProcess's successful outcomes are
`already-exited`, `terminated`, `tree-killed` and `killed`, with an empty
array of survivors. `still-alive` and `descendants-survived` are failed;
`none`, missing or unknown outcomes are incomplete. Port-free facts must both
be boolean true. A failure in any entry takes precedence over incomplete
evidence elsewhere. No new report fields, B0 meanings or producer behavior
are introduced. These cleanup outcomes do not establish descendant coverage
or authenticate historical process/port observations.

The 67-case M1B suite includes independent role deletions, duplicate records
in both orders, identical duplicates, all four successful outcomes for both
process roles, malformed records and fields, and a real local child stopped
by the existing producer. That child is a Node stand-in, not DSH; the rest
of its mount materials remain synthetic. No installation, real-host run or
coverage claim is added.
