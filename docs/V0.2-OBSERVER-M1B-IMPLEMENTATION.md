## Supervised spec and gate wiring

`spec.observer` is absent by default. When present it is a strict
`tla.observer-plan/v1` object:

```text
schema, plugin, packageRoot, version, fileCount, digest,
limits {maxBytes, maxObservations, maxPending}, cleanupTimeoutMs
```

It requires `evidenceReceipts=true` and the standard gated launcher. A custom
`hostCommand` is refused because it cannot produce the two B0 receipts.

The runner writes `runDir/observer-plan.json`; the gate is the only component
that renders the observer patch. After its actual `gateRunId` exists and the
runner's `runnerRunId`/`launchId` are available, the gate writes:

```text
runDir/observer-launch.patch.yml
runDir/observer/                  fresh empty plugin runDir
```

The 12 config fields are `enabled`, `runDir`, `traceFile`, `lifecycleFile`,
`runnerRunId`, `launchId`, `gateRunId`, `budgetRunId`, `maxBytes`,
`maxObservations`, `maxPending`, `cleanupTimeoutMs`. `gateRunId === budgetRunId`.
The upstream service run ID is never used as a gate ID. The probe and host use
the same patch list; `--dump-config` is only a synthesis check.

## Mount-probe checker

`tools/check-observer-mount-probe.mjs --input <json>` evaluates synthetic
evidence and emits `tla.observer-mount-probe/v1` with:

- `scope=mount-probe`;
- `status=probe-passed|incomplete|failed`;
- `hostVerified=false`, `coverage=unknown`;
- `binding` only `consistent` from B0 or `unproven`;
- `closed=false`.

It requires the lifecycle journal preparing/attached/stopping/stopped, a
non-degraded `host-notification` trace, read and foreground pwsh results, no
unexpected tools, both receipts, complete ledger and clean observer cleanup.
Missing evidence is `incomplete`; contradictory evidence is `failed`; it never
claims business closure or real host coverage.
