## 6. Stop and success rules

No automatic second host start. Stop/report on refusal, spawn/protection/identity
failure, missing observer attached record, degraded capture, unexpected tool,
tool error, policy exhaustion, request cap, timeout or cleanup anomaly. Retain
all original evidence; no changing policy/config and rerunning under one approval.
Observer failure remains a failed trial even if host exits zero.
The supervisor's optional observer watch must allow a bounded attachment window
inside the overall host timeout (proposed maximum 10 seconds), not fail merely
because the process has just spawned. Validate the watcher identity and journal
records rather than checking file existence. Test watcher refusal/timeout using
local child helpers. No promise that early model calls cannot race attachment:
if required probe observations are absent, the trial remains incomplete.

Report separately: authorization, command attempt, launcher/host creation,
plugin mounted, budget reserved, gate admissions, upstream arrivals/completions,
observer records and cleanup. Reconcile B0 runner/gate/budget using actual records.
ObserverPid is not launcherPid; source labels/config strings are not authentication.

The offline trial checker must require attached plus stopped journal with fixed
identity, a valid nondegraded real-origin trace, matching read/pwsh call/result
identities and safe foreground DTO, independent complete ledger/B0 mapping,
and clean owned-process/port teardown. Compare this attempt's known fixture and
marker, but do not persist raw tool content/commands into observer metadata.
Use a new report scope `mount-probe`; never call the synthetic/business closure
predicate or emit `closed`. Keep hostVerified=false and coverage=unknown.
Missing evidence => partial/incomplete, not guessed success or fabricated logs.
Report schema `tla.observer-mount-probe/v1`, exact fields schema, scope, status,
hostVerified, coverage, binding, checks. scope=mount-probe; status is probe-passed,
incomplete or failed. binding is the validated B0 binding status or unproven,
never manufactured from observer config. checks is a bounded list of
{code,ok,detail}, using stable check codes and safe bounded details, no raw tool
content or exceptions. probe-passed requires every required check true; explicit
contradictory identities/failed runtime facts mean failed, absent facts incomplete.

Even a successful trial proves only the scoped root-session mount/probe. It
does not prove all members, lossless history, historical bytes, physical ordering,
authentication, exact test-suite identity or full V0.2 repair closure.
