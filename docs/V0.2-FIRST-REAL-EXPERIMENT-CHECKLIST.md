## 2. 启动方式与保护范围

启动方式：

```
node tools/gated-run.mjs --upstream <fake-or-real> --model-requests <N> \
  --gate-port <port> --run-dir <dir> --heartbeat-file <plugin-events.jsonl> \
  --dsh-exe "<install>/DeepSeek Harness.exe" --dsh-cli "<install>/resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-desktop-host/lib/cli.js" \
  --profile stage1 --patch <overlay.yml> --prompt "<prompt>"
```

保护链（从外到内）：

1. 闸门默认拒绝：没有租约时一切模型请求 403，**不建立上游连接**；
2. 覆盖率校验：生效配置里每个启用中的 provider 实例都必须指向闸门，否则拒绝启动；
3. 插件心跳：插件 `apply()` 写出 `mounted` 才算"挂上了"；缺失/过期 → 不发租约；
4. 租约 + 计数：`used += 1` 在转发前同步完成，超限即 403（`BUDGET_EXHAUSTED`）。

保护范围（本次实验内）：

- 覆盖：单会话内单轮派工的模型请求；队长与成员（若启用 agent-teams）的请求都过闸门。
- 不覆盖：真实 `resume`/`fallback`/自动返工/跨进程并发；已转发的请求无法撤回。
- 闸门**不是**宿主级保护：它没有进 DSH 源码，只是把 `baseURL` 覆写到本地代理。

## 3. 运行形态约束

- **单会话**：一次只跑一个宿主进程，不并发、不开第二个 `--run-dir`。
- **串行**：等上一轮结束并核对证据后再决定是否跑下一轮。
- **禁用 fallback**：overlay 不配置 `fallback`；`deepseek-account` 与 pi-ai 不得成为回退路由。
- **禁用 resume**：不调用 `agent_teams_resume`，不在中断后继续同一 team。
- **禁用自动返工**：不启用 `quality-gates` 自动返工；实验中只允许一次派工。
- **不启用手机通道**：不配对、不开端口。

## 4. 请求数限制

- 闸门 `--model-requests N`：N = 2（1 次主请求 + 1 次余量），**不是**"预计会用 2 次"，而是"最多只可能出去 2 次"。
- 插件 `modelRequests` 设为 > N（例如 100）：首次实验里**不依赖插件拒绝**，让闸门做唯一裁决者（run E 已验证这种分工）。
- 硬判据：假/真上游服务端记录条数 == 闸门 `allowed` 计数 == 实际放行数；第 N+1 次必须表现为 403 且服务端**零新增**。

## 5. 输入与输出 Token 约束

- 输入：prompt 固定为一句短指令（≤ 40 tokens），任务不再追加文件内容；`messageCount` 预期为 1。
- 输出：要求单词/单行回答（如 `READY`）。**注意**：本轮没有核实 overlay 里 `maxTokens` 的字段名，因此**无法用配置硬限输出长度**；只能靠指令约束 + 运行后核对 `usage`。这一条是已知缺口，不得写成"输出已被限死"。
- 缓存：只使用无缓存命中的新请求；缓存价缺失时估算记 `unknown`，不得按输入价冒充上界。

## 6. 预估费用与可接受上限

按宿主自带目录价（USD / 1M tokens，`deepseek-flash`：输入 0.30、输出 1.20）：

- 单次请求上界（输入 ≤ 8k、输出 ≤ 1k）：`8_000×0.30/1e6 + 1_000×1.20/1e6 = 0.0024 + 0.0012 = 0.0036 USD`
- 2 次请求上界：**≈ 0.0072 USD**
- 若误用 `deepseek-v4-pro`（1.32 / 3.96）：单次 0.01456 USD、2 次 ≈ **0.029 USD**

**可接受上限：0.10 USD**（约为上界 14 倍余量，覆盖重试与计费口径差异）。超过即停止并报告。
该数字是**算术上界**，不含缓存命中折扣、峰谷价、供应商调价与汇率；它与账单可能不一致。

## 7. 停止条件

任一命中即停止（不再发起新请求）：

1. 闸门出现任何 `denied`（`BUDGET_EXHAUSTED` / `NO_LEASE` / `LEASE_EXPIRED` / `REVOKED`）；
2. 心跳缺失或过期（启动器会撤销租约并终止宿主）；
3. 宿主非零退出或超时；
4. 上游服务端记录数 > 闸门放行数（说明有请求绕过了闸门）；
5. 生效配置里出现任何 `unguarded` provider 实例（应在启动前就被拒绝）；
6. 出现 `resume` / `fallback` / 自动返工的行为迹象；
7. 估算或账单超过 0.10 USD。

## 8. 运行后的用量与账单核对

1. **请求条数**：上游日志（`requests.jsonl` 或供应商侧记录）与 `gate-summary.json` 的 `gate.used`/`allowed` 逐条对齐；
2. **宿主用量**：宿主输出的 `usage`（输入/输出/缓存读/缓存写）写入运行证据，与闸门计数分开报告（`modelRequests` ≠ tokens）；
3. **供应商账单**：只能以供应商控制台为准，可能有延迟；本清单不承诺本地能自证计费；
4. **差异记录**：把"预估 vs 宿主 usage vs 供应商账单"三者差异写清楚，差异不解释成"免费"。
