## 3. 边界与解释

- **同一条路径，通道不同，结果不同**：`tests/.scratch/` 与 `docs/` 对宿主特权文件工具可写，对常态沙箱内的普通子进程不可写；Git 元数据目录对普通子进程（含 `git add`/`commit`）不可写。
- 工作区根对普通子进程可写，但 `tests/`、`docs/` 等既有子目录不可写；这**不等于**整棵工作区可写。换目录没有换掉权限模型。
- `write`/`edit` 走宿主特权通道，所以能在子进程被拒的目录落盘；**不能**据此推断普通开发命令也能写。
- Git 元数据位于工作区之外，工作区可写不等于 Git 可写；提交需要单独放行。
- 与 `docs/V0.2-ROUND13-ENV-BLOCK-2026-10-19.md` §3 的推断相容（根目录 ACE 未传播到既有子目录），但本轮未做 ACL 逐对象验证，不把该推断写成已证实的根因。
- 一次性外层放宽只对当次命令生效，进程仍以普通用户运行；未改 ACL、未改 profile、未改系统执行策略、未提权。

## 4. 最小复现

```powershell
$ws = 'D:\AI\TLA\workspaces\v0.2-component-reuse'
Set-Content -LiteralPath (Join-Path $ws 'tests\.scratch\probe.txt') -Value 'x'   # 常态：失败
node -e "require('fs').writeFileSync(process.argv[1], 'x')" (Join-Path $ws 'tests\.scratch\probe.txt')  # 常态：失败
git -C $ws add -- docs/VERSIONING.md                                             # 常态：index.lock 失败
# 对照：工作区根
Set-Content -LiteralPath (Join-Path $ws 'probe.txt') -Value 'x'                 # 常态：成功
```

`git -C <工作区> add` 的失败点在 `<gitdir>/index.lock`，不在工作区；修复工作区权限不会自动修好 Git 元数据权限。
