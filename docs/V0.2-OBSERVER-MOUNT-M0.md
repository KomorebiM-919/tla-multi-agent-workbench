Use the existing reviewed plugin's ESM export shape (`name`, `inject=[]`,

Do not modify or import the budget plugin or reuse its reviewed build digest.

Package layout preserves relative imports: root package.json/index.js plus

Keep the seven-file manifest as a historical/core package contract; use a new

Importing the candidate does nothing. `apply` with enabled=false returns without
file access or subscriptions. enabled=true validates all configuration first,
then opens fresh files and registers exactly the reviewed passive events.
No async dynamic import race: attached cannot be reported before setup succeeds.
If the actual loader lifecycle is insufficiently established, implement the pure
composition factory and leave the loadable entry explicitly unsupported.

Pure composition accepts an explicit context and injected I/O for tests.
All fake-context tests must declare simulated-dispatcher. The real entry may

and construct trace and journal from the same validated origin/trace identity.
Do not relabel an existing simulated trace. hostVerified stays false.

## 3. Configuration and lifecycle

Exact enabled configuration fields:
enabled, runDir, traceFile, lifecycleFile, runnerRunId, launchId, gateRunId,
budgetRunId, maxBytes, maxObservations, maxPending, cleanupTimeoutMs.
enabled is boolean. For enabled=false, accept only {enabled:false}; for true,
all fields are required and unknown fields are rejected. IDs use B0 validators;
launchId is UUID v4. Gate/budget IDs must agree, but remain configuration claims.
Limits retain B1 ranges. cleanupTimeoutMs is a safe integer in 1..5000.
No prompt, raw argv, environment serialization, credentials or role inference.

runDir must be an explicitly selected existing empty directory; both output
paths must be distinct fresh children, physically contained inside it. Do not
use the runDir shared by B0 receipts: the future launcher must provide a fresh
observer subdirectory. Use reviewed physical ancestor checks, including Windows
reparse probe unavailable => blocked. No malicious TOCTOU guarantee is made.
No automatic creation of profile folders or repair of paths/permissions.

Order: validate -> exclusive journal/header preparation -> fresh trace/header
-> register stop owner and passive callbacks -> attach success -> attached
journal record. Any partial setup rolls back only owned handles/subscriptions.
An attachment failure must not produce attached. If writing attached fails,
latch failure, disable callbacks and stop this observer; do not alter tool results.
Host loaders may warn and continue after apply failure: absence of attached is
failure, never proof that the host itself refused to run.

Register the context disposal owner through an independently sourced lifecycle
hook, not a guessed async host guarantee. Explicit controller stop must also be
available to the offline composition factory. Stopping twice has no additional
registration, footer or journal writes. Late callbacks become inert first.

## 4. Bounded cleanup observation

Preserve synchronous stop() and its existing failure/pending semantics. Add an
optional waitForCleanup({timeoutMs}) operation to the host bridge/controller:
- valid timeout range 1..5000 ms; no implicit infinite wait;
- calling it before stop is rejected without initiating stop implicitly;
- it observes the actual retained disposer settlement state, not polling a
  guessed property or fabricating completion from elapsed time;
- returns a detached snapshot {status,pendingCount,failedCount}, status one of
  settled/failed/timeout; counts are nonnegative safe integers;
- settled requires zero pending and zero failures; any known failure gives
  failed (counts still show other pending work); timeout means deadline reached
  with pending and no already-known failure;
- a deadline does not cancel underlying disposal; callback guards remain inert;
- clear waiter timers on settlement and never upgrade the old stop().ok=false.

Every waiter is bounded; repeated calls may observe later settlement but cannot
rewrite earlier snapshots. Count synchronous failures and promise rejections.
Do not propagate rejection/error text. Timeout/failure in a mount's final
journal remains non-success even if disposal eventually finishes later.

The entry tries bounded cleanup and writes a final safe lifecycle record if
possible. Host may not await disposal callbacks, and process exit can cut this
short. Missing final records mean incomplete shutdown. No promise of guaranteed
flush/durability; journal close failure cannot be inferred from its own bytes.
Return close failure separately to the controlling caller, as with B1 writer.

## 5. Lifecycle journal: tla.observer-lifecycle/v1

Exclusive UTF-8 JSONL, at most 16 records/64 KiB total, each record <=4 KiB.
All records have exactly:
schema, seq, phase, traceId, origin, runnerRunId, launchId, gateRunId,
budgetRunId, observerPid, code, health.
schema fixed above; seq consecutive positive safe integer. traceId fresh UUID
per observer attachment, matching trace header. origin is B1 origin enum.
IDs are the validated configuration claims. observerPid is this process's PID,
not the B0 launcherPid and not independently attested DSH identity.

phase: preparing, attached, stopping, stopped, failed. Initial preparing has
code=null, health=null. Attached only follows successful setup, health=null.
Stopping precedes cleanup. Stopped requires successful writer finalization and
confirmed synchronous/bounded cleanup; health records the final snapshot.
Failures may follow any nonterminal phase; no later attached/stopped can erase
failed. Final phase occurs at most once. No observer tool events in this file.

code: null, CONFIG_INVALID, PATH_BLOCKED, ATTACH_FAILED, WRITE_FAILED,
CLEANUP_FAILED, CLEANUP_TIMEOUT, CLOSE_FAILED. Fixed codes, no exception body.
health: null or exact object {writerOk,cleanupState,ownershipUncertain}; writerOk
is boolean or null; cleanupState is not-started/pending/settled/failed/timeout;
ownershipUncertain is boolean. Stopped requires writerOk=true,
cleanupState=settled, ownershipUncertain=false, code=null. If contradictory
failure states need to be retained, failed record health plus code must preserve
the primary stage rather than promoting success. Other detailed diagnostics
remain in trace/controller health; do not invent a full business verdict here.

Journal identity matching is local consistency only. No new bundle binding
promotion or use as a budget lease, authentication, coverage or file-byte proof.
Immutable reader rejects malformed/unknown fields, sequence/transition errors,
mixed identities or missing terminal phase. Inspection is bounded, never repairs
the original. Source records themselves can be forged by a process with access.

## 6. M0 implementation and self-check package for DSH

Implement entry/pure composition, lifecycle contract/reader, bounded cleanup
wait and isolated candidate manifest/assembly as one offline package. No profile
activation, provider changes, new dependencies, runner/gate activation flags or
automatic installation. Do not change global/prepend defaults or add global:true.

Required tests use fake contexts, real temporary files and controlled promises:
- disabled import/apply has no filesystem/subscription side effects;
- strict config/identity/physical paths/limits, fresh output collisions;
- normal attach/stop plus exact journal transitions and same trace identity;
- retained callback after failed registration, partial attach/journal failure;
- multiple async disposers in both orders, reject/resolve mixtures, never-settle,
  deadline, repeated wait/stop, pre-stop wait, timer release and detached results;
- footer/close/journal failures preserve primary failure and prevent false stopped;
- no raw config/arguments/error canaries in trace/journal/health;
- fake data always simulated, default-off and old B0/B1 contracts remain valid;
- full payload from fixed Git blobs, fresh autocrlf=true checkout and archive
  agrees with new manifest, imports independently and executes fake mount/stop;
- malformed/mixed/oversized journal and missing terminal record remain incomplete.

Complete first-pass counterexample/positive/boundary/compatibility checks,
actual exits, final diff/privacy/docs review. Related B0/B1 and V0.1 tests are
required; unrelated green suites need not be repeated mechanically. Report
blocked/skipped checks honestly. Keep all historical probes/manifests. Make
local commits only and hand back for independent review before publication.
