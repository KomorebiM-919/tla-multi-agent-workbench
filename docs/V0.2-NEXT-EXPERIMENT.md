多会话并发、跨进程预算、生产可用性。

## 4. 确切命令（唯一需要升级的一条）

```bash
# 外层：一次性 danger-full-access；宿主内部仍是 workspace-write
# 参数由 tools/experiment-command.mjs 生成并离线校验（占位符不得进入真实命令）
$env:DSH_HOME = '<repo>\tests\.scratch\v02-stage1\dshhome'
$env:TLA_STAGE2_FAKE_KEY = 'stage2-fake-key'
node tools/gated-run.mjs \
  --profile stage1 \
  --patch <new-overlay>.patch.yml \
  --project-cwd <new-project> \
  --run-dir <new-run-dir> \
  --gate-port 18921 \
  --upstream http://127.0.0.1:18920 \
  --upstream-health-url http://127.0.0.1:18920/health \
  --upstream-run-id upstream-next \
  --model-requests 40 \
  --lease-ttl-ms 6000 \
  --heartbeat-max-age-ms 4000 \
  --heartbeat-file <new-run-dir>/plugin-events.jsonl \
  --gate-log <new-run-dir>/gate-events.jsonl \
  --summary <new-run-dir>/gate-summary.json \
  --timeout-ms 300000 \
  --require-file src/sum.mjs --require-file src/note.txt --require-file test/sum.test.mjs \
  --prompt '<captain prompt>' \
  --dsh-exe '<path-to-host-exe>' \
  --dsh-cli '<path-to-host-cli.js>'
```

要点：

- `--prompt` 是队长提示词；启动器不接受 `--captain-prompt`，也不接受 `--` 之后的自由参数。
- `--dsh-exe` / `--dsh-cli` 必填：启动器要自己抓 `--dump-config` 来核对 provider 覆盖，不能由调用方另给一份。
- `--model-requests 40`：本次上限（历次 closure 单轮最多 14，40 给足返工 + 复审），不允许上调。
- `--require-file`：项目里必须存在的文件（含成员要读的 `src/note.txt`），防止空目录冒充。
- 升级只覆盖这一条命令；启动器再以 `--permission-mode workspace-write` 起宿主，等价于"外层 Medium、内层 workspace-write"。

## 6. 预期事件序列（每步都可判定）

| # | 期望 | 判定依据 |
| --- | --- | --- |
| 1 | 闸门启动、宿主启动、插件挂载并立即写 heartbeat | `gate-summary.json` 有 `lease`、`plugin mount` 事件；首个请求不被 `PROOF_NO_HEARTBEAT` 拒绝 |
| 2 | captain 建队成功 | 假模型收到 `agent_teams_create`，响应 `is_error=false` |
| 3 | captain 轮询，member 认领 t1 | 出现 `member` 会话请求；`claim` 成功回显 `attempt_id` |
| 4 | member 读 `src/sum.mjs`，再读 `src/note.txt` | 两条 `read` 的 `tool_result` 都在 `is_error=false` |
| 5 | member 写 `src/note.txt` **成功** | `tool_result` 无 `file has not been read`；文件 sha256 变化 |
| 6 | member 实现 v1，跑测试 → 红 | 测试输出含失败行，`is_error=false`（工具本身成功） |
| 7 | 创建复审任务，reviewer 拒绝 | 复审结果 `is_error=false` 且文本含"拒绝/不通过" |
| 8 | 返工后再次复审 → 通过 | 复审文本含 `0 failed`；同一文件再次被写 |
| 9 | 收尾，宿主退出码 0 | `result=host-ok`，`exitCode=0` |
| 10 | 账本 `COMPLETE`，关联 ID 1:1 | `tools/recompute-ledger.mjs` 四段齐全且 `correlation.allPaired=true` |

期望请求数：约 30（captain 6、member 24），上限 40。

**判定规则**：第 5、6、8、9 步必须**同时**满足三项信号 —— 工具返回的 `tool_result`（含 `is_error`）、测试命令的**退出码**、以及 `gate-summary.json` 与账本里的**完整总结**；不能仅凭文本里出现 `0 failed` 或文件名就判成功（`repair4` 曾把错误文本里的文件名当成完成证据）。

## 7. 停止条件（任一命中就停，不重试）

1. 放行数达到 40 仍有未完成的推进；
2. 出现任何非预期的 403（`PROOF_*`、`BUDGET_EXHAUSTED`、`LEASE_*`）；
3. 宿主启动前拒绝（`CONFIG_*`、`PROVIDER_NOT_GATED`、`PLUGIN_NOT_VERIFIED`）；
4. member 写盘失败在 `SetFileSecurityW` / `SetNamedSecurityInfoW`（ACL 路径，不是本次要证明的东西）；
5. 引擎连续两次 `NO_PROGRESS`，或触发 `NO_PROGRESS_LOOP`（引擎默认阈值 3，已由 `tests/v02-reactive-model.test.mjs` 的直接反例断言）；
6. 账本 `INCOMPLETE` 或关联 ID 有未配对项；
7. 出现任何指向**非** `127.0.0.1` 的请求；
8. 项目里出现预期之外的文件改动（预算外副作用）。

停止后：保留 `run-dir` 全部原始日志，写"失败在哪一步、证据路径、下一步要修什么"，**不**当场改夹具再跑。
