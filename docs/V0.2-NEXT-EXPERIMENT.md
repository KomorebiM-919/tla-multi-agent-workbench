## 4. 确切命令（唯一需要升级的一条）

整轮实验由**一条**命令托管：监督器自己起假上游、等就绪、校验 `runId`、起受保护宿主、监视、收尾。
不再手工先起服务再起宿主——§18 的失败就是那样来的。

```bash
# 外层：一次性 danger-full-access；宿主内部仍是 workspace-write
# 1) 用命令生成器产出并离线校验 spec（退出码必须为 0）
node tools/experiment-command.mjs \
  --dsh-exe '<path-to-host-exe>' --dsh-cli '<path-to-host-cli.js>' \
  --dsh-home '<repo>\tests\.scratch\v02-stage1\dshhome' \
  --profile stage1 \
  --project-cwd '<new-project>' --run-dir '<new-run-dir>' \
  --gate-port 18921 --upstream-port 18920 --model-requests 40 \
  --require-file src/sum.mjs --require-file src/note.txt --require-file test/sum.test.mjs \
  --prompt '<captain prompt>' \
  --fake-server '<repo>\tests\.scratch\v02-stage2\fake-model-server.mjs' \
  --policy '<repo>\tests\.scratch\v02-stage2\closure\policy.json' \
  --pin-source '<source sha>' --pin-fixtures '<fixtures sha>'

# 2) 生成器只打印这一条；它就是需要升级的那条
node tools/experiment-runner.mjs --spec '<run-dir>\..\experiment-spec.json'
```

要点：

- `--prompt` 是队长提示词；启动器不接受 `--captain-prompt`，也不接受 `--` 之后的自由参数。
- `--dsh-exe` / `--dsh-cli` 必填：启动器要自己抓 `--dump-config` 来核对 provider 覆盖，不能由调用方另给一份。
- `--model-requests 40`：本次上限（历次 closure 单轮最多 14，40 给足返工 + 复审），不允许上调。
- `--require-file`：项目里必须存在的文件（含成员要读的 `src/note.txt`），防止空目录冒充。
- `--fake-server` / `--policy`：假上游脚本与反应式策略；少任一个就只给旧式单条启动命令，不给监督命令。
- `--pin-source` / `--pin-fixtures`：固定执行源码与夹具 SHA。**两个都必须给**：只给一个时监督器仍会核验，但缺的那个只能记 `unknown`，不足以声称"这次跑的是哪一版"；`supervisorSpecFor` 在带 pins 时置 `requirePinned: true`，没 pins 的实验包不算数。
- spec 里同时带 `repoRoot`：固定来源的判断必须对着**执行用的那个检出**做，而不是对着生成命令时的当前目录。
- 生成器打印的 `runner-<runId>.json` 会记录 argv、相位、健康结果、进程归属与 `teardown`（含 `treeProof`）；宿主侧 `gate-summary.json` 与 `plugin-events.jsonl` 仍是**独立**证据，两者不能互相替代。
- 升级只覆盖**这一条** `experiment-runner` 命令；它再以 `workspace-write` 起宿主，等价于"外层 Medium、内层 workspace-write"。
- **不要把命令写成 `.ps1` 再执行**：2026-10-18 第三次尝试第一次就是这样，被 PowerShell 执行策略拦下（`UnauthorizedAccess`，"禁止运行脚本"），白白消耗一次审批。直接内联执行。
