# V0.3 首批桌面壳：实现与验证记录（2026-11-04）

本记录对应分支 `feat/v0.3-desktop-ui`，基线 `95d4e7d`，工作区为 C 盘独立仓库（见
[`VERSIONING.md`](VERSIONING.md) §2.1）。范围与依赖均已由用户预先批准，本批不新增依赖。

## 1. 交付范围

- 新增独立子工程 `desktop/`，仓库根 `package.json`（V0.2 observer 包）与冻结内核未改动。
- 中文 TLA 桌面窗口，暖白三栏布局：左侧项目导航（256px）／中间团队看板／右侧角色详情（344px）。
- 初始团队模板六个角色：用户总控制（人类）、Codex 主管、Kimi 需求理解、DeepSeek 开发、GLM 辅助、MiMo 前端；
  点击角色卡在右侧看详情。
- 界面统一标注“初始团队模板 · 尚未连接模型”，并有一段状态说明，声明不产生真实回复、余额或运行状态。
- 主进程加固：`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`、`webviewTag: false`；
  拒绝新窗口、外部导航、`<webview>` 挂载与全部权限申请；只注册 `tla:app-info` 一个 IPC 通道并校验调用方 frame。
- Windows `dir` 便携打包（electron-builder），产物目录 `desktop/release/win-unpacked/`。

本批**没有**实现：聊天、智能分工、API 接入、自动替补、余额/用量、真实仓库读取、登录与审批流。

## 2. 依赖（精确版本，lockfile 已生成）

`electron 45.2.1`、`react 19.3.1`、`react-dom 19.3.1`、`vite 8.3.5`、`@vitejs/plugin-react 6.2.1`、
`electron-builder 26.18.0`；全部为 `devDependencies`，应用本身没有运行时依赖
（渲染层由 Vite 打进 `renderer-dist/`，主进程只用 Electron 内置模块）。

## 4. 启动验证：本机受限会话被阻塞，未取得窗口截图

在 DSH 受限会话里直接启动打包产物，Chromium 无法建立 mojo 通道，进程在创建窗口前退出：

```
FATAL:mojo\public\cpp\platform\platform_channel.cc:187] Check failed: . : 拒绝访问 (0x5)
ERROR:crashpad_client_win.cc:457] OpenProcess: 拒绝访问 (0x5)
```

同一现象出现在 Electron 45.2.1 与系统自带 Edge（`--headless=new`）上，属于会话级限制而不是本工程缺陷；
用诊断探针（只写日志的极简主进程）复现了同样的崩溃，进程在 `app ready` 之前以 `0xC0000005` 退出。

因此本批**没有**完成“双击打包 exe 并截图”的验证。需要在普通用户桌面会话里由人工双击
`desktop\release\win-unpacked\TLA.exe` 复核，验收前不得声称“已实际启动”。

已知的额外前置条件：如果从继承 `ELECTRON_RUN_AS_NODE=1` 的 shell 启动，exe 会被当成 Node 运行而不开窗，
人工复核时应使用资源管理器双击，或先清除该环境变量。

## 5. 遗留问题

1. 打包 exe 尚未在真实桌面会话中启动验证（见 §4），需要人工复核并补一张窗口截图。
2. 仍使用 Electron 默认图标，没有自定义 `.ico`；签名也未配置（`dir` 目标不签名）。
3. `electron-builder` 的依赖树收集会执行 `npm ls`，在受限沙箱下 spawn 失败；本工程用
   `build.beforeBuild` 钩子声明“node_modules 由外部处理”来跳过它（本工程确实没有运行时依赖）。
   以后若加入运行时依赖，必须删除该钩子。
4. 打包与启动依赖本机便携 Node 24.22.2（`.tools/`，不入库）；换机需按 `desktop/README.md` 重新准备。
