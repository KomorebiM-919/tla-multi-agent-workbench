# V0.2 live-evidence Phase A: capability audit and run-artifact bundle

Date: 2026-10-21. Baseline: `941f8b102d69f42bc4e98fc9f77983eef6c5fc62`.
This is the Phase A offline implementation from
`docs/V0.2-LIVE-EVIDENCE-DESIGN.md`. It does not add an observer, does not start
DSH or a fake model, and does not integrate into acceptance or `collectEvidence`.

## What was added

- `tools/audit-capture-capabilities.mjs`
  - validates an analyst-authored `tla.capture-capabilities/v1` report against
    explicit source-ID-to-file mappings;
  - checks exact entry bytes, SHA-256, optional container SHA-256, line locators,
    required capability IDs, statuses, unknown fields and issue references;
  - never imports, executes, installs or probes the source.
- `tools/bundle-run-evidence.mjs`
  - validates an explicit private selection file and copies selected artifacts
    into a fresh output directory;
  - hashes and verifies every copied byte, rejects source changes during capture,
    enforces artifact/byte limits, and writes `manifest.json` last;
  - emits `tla.run-evidence-bundle/v1` with `hostVerified: false`;
  - keeps binding `unproven` and does not infer IDs from CLI arguments, times or
    PIDs.
- `tools/lib/evidence-contracts.mjs`
  - shared JSON, hash, relative-path and byte-reading checks used by both tools.
- `tests/v02-capture-capabilities.test.mjs`
- `tests/v02-run-evidence-bundle.test.mjs`
- `docs/V0.2-LIVE-EVIDENCE-PHASE-A.md` (this file)

No existing checker, gate, collector, acceptance predicate, experiment spec,
profile or plugin was changed. The frozen handoff MANIFEST is untouched.

## Commands

Capability audit:

```text
node tools/audit-capture-capabilities.mjs \
  --report <report.json> \
  --source host=<extracted-host-entry-file> \
  --source agent-teams=<team-entry-file> \
  [--container host=<archive>] [--json]
```

Bundle assembly:

```text
node tools/bundle-run-evidence.mjs \
  --selection <private-selection.json> \
  --out <fresh-output-directory> \
  [--expected-runner <id>] [--expected-gate <id>] [--expected-budget <id>] [--json]
```

Both tools accept only explicit paths supplied by the caller. They do not search
profiles, home directories, credential stores or unrelated logs. The selection
file and source map contain private paths and must stay local; only the generated
bundle contents and redacted review material may be published after separate
review.

Exit conventions, separate from the migration-test 0/1/2 convention:

| tool | 0 | 2 | 1 |
|---|---|---|---|
| audit | valid report (unknown capabilities allowed) | invalid/incomplete data | CLI or I/O failure |
| bundle | `ASSEMBLED` | `INCOMPLETE` or invalid input | CLI, I/O, cleanup or output failure |

Zero is never a readiness, host-verification or live-acceptance statement.

## Capability audit result for this machine

The host source is inside `<dsh-install>/resources/app.asar`. The existing Node
runtime and tools have no archive reader, so the host entry bytes cannot be read
without adding a dependency. The audit therefore records **host unknowns** rather
than inventing host hooks.

The readable team package was audited as an exact entry:

- component: `agent-teams`;
- package version: `0.1.25`;
- entry: `package.json` (repository-relative within the package);
- bytes: `13124`;
- sha256: `3284b48e818773cf8e4880da86fbd7bc61ae46afa1d4087dff80e69236b42eb3`.

All nine capabilities were left `unknown`. No source-supported claim was made,
because the audit did not establish payload, dispatch, result delivery, member
scope and error propagation from the readable team entry. The validator returned
exit `0` for the valid report with nine unknowns and one `HOST_SOURCE_UNAVAILABLE`
issue; that means the report format is valid, not that the host can capture
anything.

Actual host audit is blocked on an explicit archive-reading decision. The tool
does not install `asar` or any other package.

## Bundle behavior and current material

The bundle accepts only these roles: `runner-summary`, `launch-receipt`,
`gate-summary`, `gate-events`, `budget-events`, `upstream-events`,
`observer-events`, `capture-capabilities`.

A valid bundle can contain a runner summary plus explicit local artifacts, exact
hashes and a manifest. It cannot prove a live run happened, cannot prove member
calls, and cannot prove a runner-to-gate parent-child mapping without a real
launch receipt that records both identities and the created child. The current
bundle therefore always reports `binding.status: "unproven"` and emits
`RUN_BINDING_UNPROVEN`; a missing receipt is retained as an issue, not filled
from expected IDs.

Run-bearing artifacts are inspected conservatively: explicit JSON fields
`runId`/`runnerRunId`/`gateRunId`/`budgetRunId` and JSONL `runId` values are
recorded; conflicting runner or gate/budget identities make the bundle
`INCOMPLETE`. Unknown or unparseable run-bearing formats are not guessed. The
Phase A tool does not claim that a matching gate/budget ID proves a runner
mapping.

`ASSEMBLED` still permits non-fatal issues such as a missing observer, missing
receipt or unproven binding. It only means the selected files were copied and
hashed, a runner summary was present, and no fatal identity/assembly conflict was
detected. It never means business closure.

## Limits and refusal conditions

- at most 32 artifacts;
- at most 8 MiB per artifact;
- at most 64 MiB total copied bytes;
- manifest at most 1 MiB;
- JSON nesting at most 32 levels;
- no absolute/drive/UNC/device/traversal/dot-segment/alternate-stream/reserved
  bundle paths, no backslashes;
- `manifest.json` is reserved;
- source symlinks are rejected; output must be a new directory;
- source metadata and hash changes during capture are rejected;
- copied bytes are re-read and hashed after writing;
- limits are refusals, not truncation.

Lexical path safety is not physical containment, and a stable read is not a
TOCTOU-free snapshot. Source paths can be reparse shapes that Node's `lstat`
does not expose; the tool refuses symlinks but does not claim to solve opaque
Global reparse targets. This is an explicit trust-boundary limitation.

## Design review: points for Codex before Phase B

1. **Host archive reading.** Decide whether a supported, reviewed archive reader
   may be used, or whether host entries must be supplied already extracted. The
   current tool deliberately does not install one; all host capabilities remain
   unknown.
2. **Launch receipt schema.** The design describes a receipt but defines no
   fields or join key. Phase A cannot implement `consistent` binding from it and
   does not synthesize one. A later runner/gate change must define the exact
   receipt bytes and how the child identity is recorded.
3. **Run-bearing artifact schemas.** Phase A recognizes only explicit JSON run-ID
   fields and JSONL `runId`; the exact runner/gate/budget event schemas must be
   fixed before conflict detection can be normative. Unknown formats are not
   evidence.
4. **Physical containment and reparse.** The source bundle cannot establish
   physical path safety for opaque reparse shapes. Decide whether Phase B needs a
   native helper, a stricter file-handle based capture, or an explicitly accepted
   limitation.
5. **Observer, ordering and byte provenance.** These remain Phase B decisions.
   This phase deliberately adds no observer, no partial-order protocol and no
   claim that a log arrival order or final file hash proves historical bytes.

## Tests and self-check

Invented materials only are committed. The two test files cover:

- unknown capabilities not promoted, missing evidence for `source-supported`,
  out-of-range locators, duplicate/missing capabilities, unknown fields, hash and
  byte mismatches, CRLF/LF;
- valid and incomplete bundles, duplicate IDs/paths, traversal/reserved paths,
  limits, conflicting runner and gate/budget IDs, expected-ID mismatches, source
  changes during capture, copied-byte mismatches, cleanup failure preserving the
  original error, and CLI exits.

The public tests do not include real run logs, host paths or private mappings.
Actual source audit and any real bundle remain local and are not published by
this work package.
