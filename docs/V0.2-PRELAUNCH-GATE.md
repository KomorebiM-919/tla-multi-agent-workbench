# V0.2 启动闸门：预算保护不能依赖"插件已经装好"

状态：本地实验实现并验证。**未接入任何真实模型端点，不构成宿主级强制保护**。日期：2026-10-18。

## 1. 要修的问题

阶段 1/2 的事故记录表明：预算拦截逻辑放在 DSH 插件里不可靠。

- 插件 `apply()` 抛错时，宿主只打印 `dsh: warning: 1 entry did not activate` 并**继续运行**；实测随后在无预算状态下发出 2567 次模型请求，直到手工杀进程。
- 因此"插件已安装/配置里存在该条目"不能证明"保护生效"；"某个状态变量说 mounted"同样不能。

结论：判定"能不能发请求"的位置必须独立于被保护的插件，并且**默认拒绝**。

## 2. 设计：三层职责分离

1. **预算闸门（gate）**：进程内的本地 HTTP 代理，只绑 `127.0.0.1`，只有一个上游（也必须是回环）。默认拒绝，只有在"持有有效租约 + 额度未用尽"时才建立上游连接并放行。额度用尽/租约过期/已撤销/正在关闭 → 返回 403 `TLA_GATE_DENIED`，**不建上游连接**。
2. **插件（attestation only）**：`tla-prelaunch-budget` 不再承担强制。它只做两件事：挂载时写 `mounted` 心跳、每次预占写 `reserved`/`rejected`。它缺不缺失都不影响闸门的默认拒绝。
3. **启动器（preflight + lease）**：`tools/gated-run.mjs` 在启动宿主前校验**生效配置**里的 provider `baseURL` 指向闸门；不指向就退出码 3 且不启动宿主。随后启动宿主，读到新鲜 `mounted` 心跳才发租约，并按 `ttl/3` 续期；心跳过期 → 撤销租约并 SIGTERM。

闸门自己也能读心跳文件（`mountProof`）：宿主启动后立刻发首个请求时，插件挂载事件通常已经落盘，闸门在无租约时同步检查这份新鲜证明，命中才当场授权，同一事件只消费一次，撤销后不再重新授权。这样消除了"先等心跳再发租约"与"首个请求立刻到达"之间的竞态。

## 3. 实现文件

- `orchestration/gate/gate.mjs`：`createBudgetGate({ upstream, modelRequests, leaseTtlMs, logPath, mountProof })`；控制面 `/__tla/gate/{status,lease,heartbeat,revoke}` 仅回环可用；事件日志 `listening/lease-granted/lease-from-mount/heartbeat/heartbeat-rejected/lease-revoked/allowed/denied/upstream-error/closed`。
- `orchestration/gate/preflight.mjs`：`checkBaseUrl`（按路径段比较，避免端口前缀误匹配）、`checkProtectionHeartbeat`（缺失/过旧/未来时间都算不可用）、`decideStart`（纯函数）、`readGateStatus`。
- `tools/gated-run.mjs`：启动器；退出码 `0` 正常、`1` 宿主失败、`2` 参数/内部错误、`3` 保护未建立（宿主已终止）、`4` 运行中保护丢失。
- `tests/v02-gate.test.mjs`：7 场景 / 57 断言。

## 4. 故障注入结果

| 场景 | 触发方式 | 真实宿主请求数 | 证据来源 |
| --- | --- | --- | --- |
| 插件缺失 | 隔离 profile 不装插件，宿主直连闸门 | 上游 0；闸门 `denied=1 NO_LEASE`，宿主收到 403 后退出 | 真实宿主 run A |
| `apply` 抛错 | 心跳文件里只有 10 分钟前的陈旧 `mounted` | 上游 0（5 条请求全 403） | 夹具 |
| 心跳缺失 | 不产生心跳文件 | 上游 0 | 夹具 |
| 心跳过旧 | `mounted` 超出 `maxAgeMs` | 上游 0 | 夹具 |
| 租约过期 | `leaseTtlMs: 150` 后不续期 | 上游 0 新增 | 夹具 |
| 运行中撤销 | `revoke('HEARTBEAT_LOST')` 后再请求 | 只收到此前已放行的数量 | 夹具 |
| 正常挂载 | 插件已装、心跳新鲜、额度 2 | 上游恰好 2，第 3 次 403 | 夹具 |
| 正常挂载（真实宿主） | 插件已装、额度 1 | 上游 1，宿主退出码 0 | 真实宿主 run B |
| 额度耗尽（真实宿主） | 额度 1，脚本第一步触发工具调用 | 上游 1；第 2 次请求被插件启动前拦截，宿主退出码 1 | 真实宿主 run C |
| 保护未建立即启动 | 生效配置里 baseURL 未指向闸门 | 0（宿主根本没启动） | 夹具 |

真实宿主三次运行（`tests/.scratch/v02-stage2/run-a-gate`、`run-b-gate`、`run-c-gate`）：

- run A：`EXIT=3`、`result=host-exited-before-protection`、闸门 `denied=1 allowed=0`、上游 0 条。
- run B：`EXIT=0`、`result=host-ok`、闸门 `used=1 rejects=0`、上游 1 条、插件事件 `mounted → reserved → unmounted`。
- run C：`EXIT=1`、闸门 `used=1`、上游 1 条；第 2 次请求在插件层被拒（`MODEL_REQUEST_BUDGET_EXCEEDED`）。宿主进程内两层同时生效，闸门仍保有"再来一次就 403"的兜底。

本轮全部实验对真实外部模型的调用为 **0 次**；上游是 `127.0.0.1:18777` 的假模型服务，实验结束后端口与进程已确认释放。

## 5. 限制与未证明项

- **闸门只在"模型请求确实经由被覆写的 `baseURL`"时有效**。宿主若绕过该 provider 直连公网，闸门看不到请求。本轮用假 key + 假上游，因此没有真实外发，但这不等于证明宿主无法绕过。
- **生效配置由 CLI 的 `--dump-config` 生成**（`--dump-config` 打印 YAML 且退出码为 `-1`，判据只能是"有没有输出"），启动器校验其内容而不亲自生成。这条信任链是本实验的边界。
- 沙箱下 `spawnSync(..., { encoding })` 与默认 `spawn` 管道都会 `EPERM`，所以真实运行改由外层 pwsh 先落 dump、再 `--dump-config-from` 读入；测试内子进程必须 `stdio: 'ignore'`。
- **未验证**：跨进程/跨会话的预算共享；`resume`、`fallback`、自动返工路径；取消请求是否被供应商实际计费；宿主对"插件激活失败"的行为是否会在其他版本变化。
- 闸门是**本地实验工具，不是宿主级强制保护**：它没有进入 DSH 源码，也没有被宿主默认启用。

## 6. 复跑

```bash
node tests/v02-gate.test.mjs
node tools/gated-run.mjs --help
```

真实宿主复跑需要：隔离 profile 里装好 `tla-prelaunch-budget`、overlay 把 `llm-deepseek.baseURL` 指向闸门、`apiKeyEnv` 指向假 key、假模型服务只绑 `127.0.0.1`。
