seven-file `b1-observer` set. It is **not** an installation manifest and no

The manifest records `bytes`, `sha256` and canonical Git blob for the fixed

## Dependencies and import shape

The candidate imports only Node.js built-ins and repository-local `.mjs` files.
It adds no package dependency and does not import DSH/Cordis at module load. The
entry has no top-level side effect: `apply(ctx, config)` is the only activation
point, and `enabled:false` performs no file or subscription work.

The loader export shape is deliberately **not** asserted as a host mount
contract. The candidate is a pure composition factory with `loadable=false`;
the actual DSH loader discovery/activation remains unsupported by this package.

## Configuration

Enabled configuration is strict: 12 fields, no extras or missing fields.

| field | rule |
|---|---|
| `enabled` | must be `true`; `false` only accepts `{enabled:false}` |
| `runDir` | existing, empty; output files are direct children |
| `traceFile`, `lifecycleFile` | inside `runDir`, fresh, physically safe |
| `runnerRunId`, `gateRunId`, `budgetRunId` | non-empty IDs; gate equals budget |
| `launchId` | UUID |
| `maxBytes` | 128 KiB to 8 MiB |
| `maxObservations`, `maxPending` | positive safe integers within limits |
| `cleanupTimeoutMs` | positive safe integer, at most 5000 ms |

No `global:true`, `prepend`, provider override, budget change or automatic
`ctx` discovery is included. The bridge accepts an explicit `ctx.on(event, cb)`
and keeps the returned disposer; it never calls `ctx.off`.

## Mount and stop evidence

The only evidence in this package is **fictional**:

- fake `ctx` with synchronous `on`/disposer behavior;
- fake `tools/result(exec,result)` and `session/event(session,event)` records;
- real temporary files for the trace and lifecycle journal;
- controlled promises for async disposers and cleanup deadlines.

`hostVerified=false`, `coverage=unknown`, `binding=unproven` remain unchanged.
The isolated package check imports the copied closure and performs a fake
`apply`/`stop`; it does not load a profile, call a host, or observe a real
member. The earlier `--dump-config` check is not mount evidence.

## Failure handling

- Registration failure rolls back earlier subscriptions; a retained callback
  whose removal cannot be proven sets `ownershipUncertain=true`.
- `stop()` remains synchronous. `waitForCleanup()` returns a detached snapshot
  with `settled`, `failed` or `timeout`; it never changes an earlier failure
  into success and releases its timer on settlement.
- Journal transitions are strict: `preparing → attached → stopping → stopped`,
  or `failed`; terminal state cannot be rewritten.
- Writer footer/close failures are independent observations. A primary error
  keeps its stage/code; cleanup or close failure cannot overwrite it.
- Async disposer rejection is latched; one later resolution cannot clear it.
- No raw config, prompt, arguments, exception text or credential canary is
  written to the trace, journal or health.

## Package verification

After a fixed commit, the offline checker is run as:

```text
node tools/check-observer-m0-package.mjs \
  --repo <worktree> --commit <sha> \
  --checkout <fresh-autocrlf-checkout> \
  --manifest docs/V0.2-OBSERVER-M0-PACKAGE-MANIFEST.json
```

It compares canonical Git blobs, the fresh checkout, `git archive` bytes and the
manifest, copies the closure into a new directory, imports the entry and performs
a fictional mount/stop. Exit `0` means those bytes and the offline lifecycle
agree; it does not mean the host can load the plugin.

## Install and rollback (not executed)

Future install requires separate human approval. The intended local rollback is
to remove the copied candidate directory/file set; no profile, ACL, budget
plugin fingerprint, provider list or global configuration is modified by this
package. The budget plugin (`tla-prelaunch-budget`) is independent and its
registered digest must not be changed or reused as evidence for this observer.
