# V0.2 权限预检：为什么成员写不了文件

本轮任务书（`m21080`）第一、二部分要求：先只读查明 ACL 失败，再用一个新建的最小项目做
独立权限预检，并优先在 `workspace-write` 下完成，而不是把"放宽权限"当成唯一方案。

结论先说：**预检在 `workspace-write` 下没有通过**，而且失败和项目目录本身无关。原因是
启动这条链路的进程带着低完整性（Low Mandatory Level）令牌，宿主及其工具子进程继承了这个
令牌，而宿主写文件与给自己授权都要修改 DACL，这一步在没有 WRITE_DAC 的令牌下必然失败。
按任务书要求，本文把目标、原因、范围和回滚写清楚后停止该路径，没有修改任何 ACL、没有关闭
沙箱、没有把整个宿主切到 `danger-full-access`。

## 1. 只读核对到的范围与对象

| 项目 | 观察结果 |
| --- | --- |
| 宿主实际 cwd | `gated-run` 用 `--project-cwd` 同时作为探测与启动的 cwd，宿主 `sandbox-policy.workspaceRoot` 因此等于项目目录 |
| 沙箱模式 | `sandbox-policy.mode = process.env.DSH_PERMISSION_MODE ?? 'workspace-write'` |
| 项目目录与目标文件 | 位于工作区内部、普通目录；所有者与工作区相同；`AreAccessRulesProtected=False`（DACL 未被保护） |
| 祖先链 | 整条链上没有 junction/符号链接，不是嵌套 worktree |
| 目录 ACE | `Everyone` 上有一条只拒绝 `DeleteSubdirectoriesAndFiles` 的显式拒绝；一个 AppContainer 能力 SID 有 `Write, Delete`；`Authenticated Users` 有 `Modify`；另有一条 Low Mandatory Level 的 `NW`（no-write-up）标签 |
| 已成功写入过的 V0.1 文件 | 拥有与本项目**完全相同**的继承 ACE |

也就是说：项目 ACL 不是差异来源——同一个工作区里 V0.1 轮写过文件，本轮写不进去。

## 2. 本机复现（不启动宿主，不发任何模型请求）

在同一工作区的新建最小项目 `tests/.scratch/v02-stage2/preflight/project/` 上，直接用普通进程
做四件事：

| 动作 | 结果 |
| --- | --- |
| 新建文件并写入内容 | 成功 |
| 向已有文件追加内容 | 成功 |
| 把源文件的 DACL 复制到暂存文件（`Set-Acl`） | 失败：`尝试执行未经授权的操作` |
| `whoami /groups` 的完整性标签 | 只有 `Mandatory Label\Low Mandatory Level (S-1-16-4096)` |

数据写入成功、改权限失败，正好对上宿主的两个工具实现：

- `dsh/node_modules/@deepseek-ai/dsh-fs-local/lib/index.js:75-79`：写文件时先在 `.tmpdir`
  里 stage，然后 `copyFileDaclWin32(source, destination)`，最后
  `api.setFileSecurityW(toNamespacedPath(destination), 2147483652, descriptor)`
  （`2147483652 = 0x80000004`，即 DACL + PROTECTED）。这一步需要目标文件的 WRITE_DAC。
- `dsh/node_modules/@deepseek-ai/dsh-sandbox-windows-acl/lib/types-*.js:592`：`grantWrite()`
  用 `SetNamedSecurityInfoW` 一次性写"能力 SID allow + ambient delete deny + Low 标签"；
  `:611` 把失败包装成 `SetNamedSecurityInfoW failed (Win32 5): grantWrite(<path>)`；
  `:1278`/`:1284` 对每个可写目录和 temp 目录各做一次。

上一轮真机日志里成员的两次失败正好是这两处：

- `Error: SetFileSecurityW EACCES (Win32 5): …\\src\\.sum.mjs.<id>.tmpdir\\sum.mjs.tmp`
- `Error: SetNamedSecurityInfoW failed (Win32 5): grantWrite(…\\repair5\\project)`

失败点都在"改 DACL / 打标签"，不在"写字节"。

## 3. 整条链路里的那一次预检

`tests/.scratch/v02-stage2/preflight/` 是任务书要求的最小项目：`src/note.txt` 的基线
sha256 为 `B75D356FA2847FDC02D5B829D66E45949820E673A0DA8D7209585C22F437FDC5`，
`test/check.mjs` 只在文件含 `written by preflight` 时退出 0，策略要求"写 → 回读 → 跑测试"。

| 尝试 | 请求数 | 结果 |
| --- | --- | --- |
| attempt1（策略首条 state 写错，引擎立即失败） | 1 | `EXIT=0`、`FAKE-MODEL-ENGINE-ERROR NO_PROGRESS` |
| attempt2（修正 state 后） | 2 | `write` 报 `is_error=true`，`note.txt` 哈希不变，`EXIT=0`、`result: host-ok` |

attempt2 的上游日志：`arrived` 两条；第 1 条 `accepted:true` 且有 `responded`；第 2 条
`accepted:false` 且**没有** `responded`。第 2 条的请求体（含 `write` 的失败文本）当时没被
落盘——这是一个真实的观测缺陷，已改成"决定响应之前先落盘请求体"，并让引擎失败也写
`responded{kind:'error'}`。

预检结论：在 `workspace-write` 下，**新建的最小项目同样写不进去**；与项目 ACL、嵌套
worktree、链接、以及"成员是否拿到正确工作区"都无关。

## 4. 根因

1. 这条链路的起点是被 DSH 沙箱包起来的进程，令牌是低完整性，并带有受限 SID；
2. `gated-run` 从这个进程启动宿主，宿主继承了同样的令牌，工具子进程再继承一次；
3. 宿主的写工具与 `pwsh` 工具都需要修改目标（或暂存文件）的 DACL，而 DACL 的"能力 SID
   allow + Low 标签"里**没有** WRITE_DAC 给当前令牌；
4. 于是 `SetFileSecurityW` 与 `SetNamedSecurityInfoW` 都返回 `ACCESS_DENIED`。

V0.1 的真实写入成立，是因为那一次是用户自己的 Desktop 会话（中等完整性、所有者权限完整）
在跑，不是这条低完整性链路。

## 5. 若要解除，需要什么（本轮未执行）

任务书要求：确需改 ACL / 用宿主不支持的权限 / 用 `danger-full-access` 时，交付目标、原因、
范围与回滚后停止。下面是清单，**没有执行**任何一条。

| 项 | 内容 |
| --- | --- |
| 目标 | 只让"这一条启动命令"在中等完整性、非受限令牌下运行，其余会话与现用 Desktop 不变 |
| 原因 | 宿主写文件与 `grantWrite` 需要 WRITE_DAC；受限令牌拿不到，改 ACL 也不能让受限令牌获得它 |
| 范围 | 单次启动：`node tools/gated-run.mjs … -- <DSH exe> --expose-internals <cli> …`；不改 DSH 源码、不改沙箱实现、不改项目 ACL、不改现用 profile |
| 不做 | 不关闭沙箱、不给整个宿主 `danger-full-access`、不给工作区加宽 ACE、不复制凭据 |
| 回滚 | 该命令结束后不残留任何配置；隔离 `DSH_HOME`、隔离 profile、假服务日志都留在原地不删 |
| 备选（成本更高） | 在用户自己的终端里执行同一条命令，效果等价且不需要放宽本会话的沙箱 |

不建议的方向：给项目目录加 `Authenticated Users:(F)` 或 `Everyone:(F)`——那既改不动
受限令牌能改的 DACL 结构，也会把"最小权限"变成全盘授权；也不建议改 DSH 沙箱实现。

## 6. 因此本轮能确定与不能确定的事

- 能确定：`write`/`pwsh` 失败的直接原因、失败发生在哪两行代码、以及它与项目 ACL 无关；
- 能确定：宿主在本会话里运行时，任何"写已有文件"和"给目录授权"的动作都会失败；
- 不能确定：中等完整性令牌下这条链路是否一次跑通——那需要第 5 节的一次受控启动；
- 不能声称：返工闭环已经完成。文件没有被改过，测试前后都是 `2 passed, 1 failed`。
