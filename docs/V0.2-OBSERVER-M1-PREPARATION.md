## 2. What the loader actually requires

Source references are 1-based and scoped to the entries above:
- loader Entry._init, 450-464: import module, unwrap exports, register plugin.
- loader unwrapExports, 667-672: normalize default/namespace forms.
- cordis registry resolve/plugin, 1533 onward and 1619 onward: a function or
  object exposing apply is a plugin; config and inject are passed to its fiber.
- cordis fiber callback, 1063-1072: invoke the plugin with (ctx,config).
- cordis _execute, 1135-1167: collect returned disposer functions; Promise
  results pass through safeCollect. A non-null plain controller is Invalid effect.
- cordis _unload, 1372-1385: await registered cleanup effects, contain/log errors.
- profile boot, 260-269/302-318: own the app and await root fiber disposal on
  shutdown; readiness/state is not proof that every observer fact was recorded.
- bin CLI, 239 onward: dump-config is a separate path from profile startup.

Decision: **do not flip M0 loadable=false to true**. Its apply returns a
controller for offline use and is not the correct plugin-effect return shape.
Add a separate loader-shaped wrapper. Keep the M0 factory and historical package
manifest intact as a baseline. A source-compatible wrapper is still not a
runtime-verified plugin; do not advertise a universal stable DSH API.

## 3. M1A offline wrapper assignment

Use a separate ESM wrapper/package entry (proposed host-plugin/index.js and
package.json) with the same private logical package name tla-tool-observer.
Only one entry would be selected in any future isolated profile. No new npm
dependency, dsh.bundle auto-load, network source or installation script.

The wrapper exports the reviewed named name/inject/apply shape, with no default
controller object. Disabled apply performs no I/O/subscription and returns
undefined. Enabled apply validates config, creates the controller, verifies
setup success, and returns a disposer function (or Promise<disposer>). It never
returns controller/health directly to the loader. Setup failure is a fixed-code
failure after bounded rollback; merely throwing does not certify host refusal.

The returned disposer calls the controller's single stop Promise. It awaits
bounded cleanup, retains safe health for journal/controller reporting, and
rejects with a fixed code when stop failed. No raw exception text or controller
payload in a thrown value. The host may contain this rejection, so independent
evidence must be inspected rather than trusting process exit zero.

Tests must drive a fake loader contract through module normalization,
apply(ctx,config), safe collection of its returned disposer and unload; do not
import/execute Cordis from the archive or claim this harness is live proof.
Include a negative M0-controller return example so the old mistake stays caught.
Preserve disabled and import-no-side-effect behavior, positional notifications,
no global/prepend, bounded stop, idempotence and all safe diagnostic contracts.

## 4. Origin and composition

M0 continues to default to simulated-dispatcher. A separately reviewed wrapper
path may declare host-notification when actually used as a host plugin, but this
string remains a source declaration, not authentication, coverage or hostVerified.
The production apply path chooses it internally; it is not a config field that
can relabel a previously generated trace. Trace/journal must share the exact
validated origin, traceId and run claims from one composition.

Do not widen the generic adapter by accident. Any shared bridge/factory change
to permit the wrapper origin must keep current defaults and explicit origin
validation; documented M0 simulated fixtures remain simulated. Use dependency
injection to test wrapper decisions without publishing fabricated
host-notification trace fixtures: fake-loader real-file tests select simulated
origin via a test composition factory, and production-origin wiring is tested
with a nonpersisting injected composition. No fixture becomes runtime provenance.
hostVerified=false, coverage=unknown, binding=unproven remain unchanged.

The wrapper is responsible for registering its returned cleanup effect. Do not
register a second dispose hook that races the same final journal, or assume a
ctx.on('dispose') callback is equivalent to a collected plugin effect.

## 6. M1B minimal trial proposal (not execution authorization)

Use the existing supervised local fake-model route for the first trial unless
a separately reviewed no-model startup recipe is established. No new CLI flag
is assumed; dump-config is not mount proof. Propose only one captain/session,
no team creation or repair, one known fixture read and one harmless foreground
pwsh marker. No implementation writes, PTC/background jobs, web access or paid
model. The fixture lives in a fresh project, read uses the actual file_path
schema and pwsh uses the actual description schema.

The future policy/spec must be prechecked against audited tool schemas and
bounded scheduling. Request budget remains <=40 gate admissions including
precheck, with a concrete planned count and failure branches; no automatic
restart, quota increase or second run. Supervisor owns fake upstream and
launcher. Keep loopback-only routes, workspace-write inside, default protection,
lease/heartbeat and B0 evidence receipts. Any outer sandbox allowance must be
an exact separately approved command; it is not administrator authorization.

Trial prerequisites: final source/fixture/payload pins, fresh project/runDir,
verified installed identities, full preflight, source/runtime version checks,
explicit installation/profile-change approval and separate one-run approval.
No spec/launch command is produced as executable authorization in M1A.

The later trial reader must separately report:
- actual loader-compatible setup and attached journal for the selected identity;
- trace containing the approved read and pwsh observation, with session/call
  links and safe DTO; exact file-byte history is not required or implied;
- stopped journal plus independent controller/shutdown and process cleanup
  evidence, no known capture degradation or timeout;
- complete B0 reconciliation and consistent local identity mapping, while the
  bundle's hostVerified remains false and no business acceptance is emitted.

Missing/contradictory facts => partial/blocked. A process exit zero or attached
alone is insufficient. Forced shutdown, absent terminal journal or incomplete
budget/accounting cannot be repaired after the fact. Member coverage, lossless
history, authentication, physical ordering and full repair remain unverified
even if this minimal probe succeeds.
