## 5. 版本表述（更正）

- 安装目录的 `version` 文件 `44.7.0` 是**运行时/Electron 版本**，既不是产品版本，也不是“宿主已升级到
  `0.2.1-rc.2`”的证明；它只能说明安装没有被替换。
- 产品版本应取自应用自身元数据（`app.asar` 内 `package.json`，或更新器记录的已安装版本）。
  本轮读 `app.asar` 失败（手工解析 header 时 JSON 解析报错），因此**产品版本记为未知**，
  不用 `44.7.0` 冒充 `0.2.1-rc.2`，也不沿用旧文档里的推断值。
- 插件信息来自**已安装包的 `package.json` 与文件指纹**（0.1.25 / 126 文件 / `cordis.patch.yml` sha256），
  属于安装字节元数据，不等于“宿主实际加载了该插件”；加载与否只能在启动窗口内由宿主侧证据判定。
- `--dump-config` 与 `coverage:*` / `plugin:*` 是**配置合成检查**（provider 覆盖、凭据环境变量、组件白名单、
  插件插入位置），不是版本号证明。上一份交接把“dump 通过”当作“环境一致”，口径过宽，这里纠正。
- pin 规则：`--pin-source` / `--pin-fixtures` 必须等于**已经核实过的那份执行源码与夹具**；
  不允许为了让预检通过而把旧 pin 自动替换成当前 HEAD。若源码或夹具变了，先重新核实字节，再显式改 pin。

## 6. 解除方案（更正，均不含递归 ACL）

**6.1 不做递归 ACL。** 一次递归授予需要逐对象完整备份 DACL 并能逐对象验证回滚；
现有的备份（`tests\.scratch\acl-recovery-v02\acl-backup-8d83cf92f76645208ab924259020135b.json`）
只覆盖少数路径，不足以支撑 `/T`。因此在没有逐对象备份与回滚证据前，**不执行**递归方案，
也不在脚本里写死任何能力 SID（它会随会话变化）。

**6.2 首选：一次性外层放宽的离线维护命令。** 进程不受沙箱令牌限制时，普通用户令牌带有
`Authenticated Users`，子目录的 `Authenticated Users:(I)(M)` 足以写入——这一点有当日实证：
同一天非受限运行的 `diagnose-windows-sandbox-acl` 脚本成功把报告写进了
`tests\.scratch\acl-recovery-v02\`（一个子目录）。该路线**不改变任何持久权限**，
只针对一条命令生效一次。

**6.3 Git 元数据路径单列。** 工作区里的 `.git` 是指针文件，真正的 gitdir 在
`D:\AI\TLA\tla-multi-agent-workbench\.git\worktrees\v02-worktree`（**在工作区之外**）。
“工作区可写”绝不等于“git 可写”，任何“只在 worktree 内”的授权都必须显式列出这个路径，
否则提交仍会 `Permission denied`。

**6.4 PR 与本地提交分开。** 本地 `commit` / `push` 走 git 与已授权的凭据助手；
创建 Draft PR 或更新 PR #2 走 GitHub API/网页，需要 `gh` 或凭据，与 push 权限不互相蕴含。
两者分别记“成功 / 失败 / 未尝试”，不合并成一句结论。
