# B1 corrections: path, lifecycle and inspector boundaries

Baseline: `84fb08da37df8be48067b0fc427d2c18102de54d`. This package is still
offline-only. No observer was installed, no DSH module was imported or executed,
and no host/model was started.

## Old behavior at 84fb08d

- `trace-output` treated a missing/unparseable `fsutil` probe as `available:
  false`, then accepted the path when `realpath` matched. A Global junction that
  reports `lstat=false`, `readlink=EINVAL` and `realpath=itself` could therefore
  pass; realpath identity is not a reparse proof.
- Writer `finalize()` returned immediately for `writeFailed` before closing the
  open handle. The primary write error was visible, but the handle/close outcome
  was not.
- Inspector ignored `diagnosticsDropped`; a `finalized` footer with dropped
  diagnostics could be `VALID_METADATA`.
- Inspector used a cumulative `calls.size + results.size` check after the loop
  instead of bounding unresolved associations during delivery.
- Header/footer line sizes were not checked against 16 KiB.
- Body-level source differences were reported as `CALL_CONFLICT`/
  `RESULT_CONFLICT` rather than a source-link ambiguity.
- Writer limits used a silent fallback for zero/negative/fractional/invalid
  `maxBytes` and `maxObservations`; duplicate subscription names were accepted.

## New behavior

- Resolver probe failures and unexplainable `fsutil` output throw
  `output ancestor reparse probe unavailable`; there is no realpath bypass.
- A real Junction/opaque path is refused. Tests inject `{available:false}`,
  `{available:true,reparse:true}` and a real `mklink /J`; the latter is either
  rejected as a link/reparse point or reported as an environment skip.
- After any header/observation/footer write failure, `finalize()` closes the
  handle, records `closeFailed`, and returns the primary code plus bounded
  health. Repeated stop returns the retained close state without a second close.
- `diagnosticsDropped > 0` forces `INCOMPLETE` and adds `LIMIT_REACHED`; a
  `finalized` state cannot override it.
- Pending associations are bounded while observations are delivered; overflow
  is `LIMIT_REACHED`, not a post-hoc cumulative statistic.
- Header and footer lines above 16 KiB are rejected (`HEADER_INVALID`/
  `FOOTER_INVALID`), as are oversized interior records.
- Same-key results from different sources are `SOURCE_LINK_AMBIGUOUS`, preserved
  as separate records; same-source conflicts remain `RESULT_CONFLICT`. A single
  call and result from two sources still pair.
- Invalid `maxBytes`, `maxObservations`, `maxPending` and inspector `maxPending`
  are explicit errors. Duplicate subscription names are rejected.
- Adapter callback errors remain contained; subscription rollback and stop do
  not leave tracked listeners.

## Remaining limits

`hostVerified=false`, `coverage=unknown`, `binding=unproven`. B1 is not
installed or subscribed in a host. Physical file bytes, member composition,
dispatcher identity, lossless capture, and real repair-loop closure remain
unproven. B1 installation and a real host run still require explicit approval.

## Cross-source rule (final)

The earlier inspector degraded every cross-source duplicate to
`SOURCE_LINK_AMBIGUOUS`. The final rule retains both records and accepts them
when the normalized session/call key matches and every known metadata field is
equal or unknown on one side. Changed same-source replay and known
cross-source disagreement remain conflicts; missing identity remains incomplete.
`session/event` and `tools/result` are not assumed to be physically ordered.
