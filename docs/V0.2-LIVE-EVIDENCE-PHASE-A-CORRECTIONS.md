# Phase A bundle corrections (manifest, identity, physical paths)

Date: 2026-10-21. Baseline: `f57a28d7c1d0bb828930bf2427268551778cf558`.
This is an appended correction to `V0.2-LIVE-EVIDENCE-PHASE-A.md`; the earlier
document is left as the historical Phase A record. No core checker, gate,
collector, acceptance predicate or profile was changed.

## 1. Manifest-name and path-prefix collision

The old reserved-name test compared the exact string `manifest.json`. On Windows
`MANIFEST.JSON` therefore passed, was copied, and the final `manifest.json` write
replaced it while the manifest still reported the pre-write hash.

The bundle now:

- compares each path component case-insensitively on Windows and rejects
  `manifest.json` in any case at any prefix;
- rejects file/directory prefix conflicts (`a` vs `a/b`, including case
  variants) before creating the output directory;
- reserves the same name against artifact paths before any output write;
- re-reads every artifact after all copies, before writing the manifest, and
  re-reads all artifacts plus the manifest after the manifest write;
- rejects extra output files, unreadable artifacts and any artifact/manifest
  byte mismatch, and removes the incomplete output.

The old `MANIFEST.JSON` counterexample now fails before output with
`RELATIVE_PATH_INVALID`; `a` plus `a/b` fails with
`ARTIFACT_PATH_PREFIX_CONFLICT`. No output directory is left behind in either
case.

## 2. Identity-field conflicts

The old `readRunId` returned the first recognized field, so
`{"runId":"run-a","runnerRunId":"run-b"}` silently selected `run-a`.

Phase A now defines identity semantics per supported role:

| role | namespace | fields |
|---|---|---|
| `runner-summary` | runner | `runId`, `runnerRunId` |
| `gate-summary` | run (gate/budget) | `runId`, `gateRunId`, `budgetRunId` |
| `gate-events` | run (gate/budget) | `runId`, `gateRunId`, `budgetRunId` |
| `budget-events` | run (gate/budget) | `runId`, `budgetRunId`, `gateRunId` |
| `upstream-events` | run (gate/budget) | `runId`, `gateRunId`, `budgetRunId` |

- Distinct values in one namespace in one record produce
  `RUNNER_ID_CONFLICT` or `RUN_ID_CONFLICT` and `INCOMPLETE`.
- Distinct values across records produce the same conflict.
- Gate and budget are the same run namespace: differing observed gate/budget
  values still produce `GATE_BUDGET_ID_CONFLICT`.
- Runner and gate/budget are different namespaces: a normal `runnerRunId=run-a`
  and `gateRunId=gate-a` remain valid.
- A known but role-unsupported field produces `RUN_ID_FIELD_UNSUPPORTED`.
- A non-string or empty ID produces `RUN_ID_TYPE_INVALID`.
- No recognized field leaves the namespace unknown; no value is synthesized.

The `{"runId":"run-a","runnerRunId":"run-b"}` case now exits 2 with a locatable
`RUNNER_ID_CONFLICT`; the positive runner/gate pair remains `ASSEMBLED`.

## 3. Physical path boundary

The old code checked only the leaf file. `sourcePath=<junction>/runner.json`
passed when `runner.json` itself was regular.

The bundle now checks the source leaf, every existing source ancestor, the output
parent and its ancestors before copying:

- `lstat` symbolic links are rejected (`PATH_ANCESTOR_LINK`);
- `realpath` differences are rejected (`PATH_ANCESTOR_REPARSE`);
- on Windows a `fsutil reparsepoint query` probe is required; a reparse tag is
  rejected and a non-reparse result is accepted;
- if `fsutil` is unavailable or its output cannot be interpreted, processing
  stops with `PATH_SAFETY_PROBE_UNAVAILABLE`; the tool does not silently fall
  back to lexical path checks;
- drive roots are checked for link/realpath identity but are not reparse-probed.

A real `cmd mklink /J` junction at the source-parent level and at the output-parent
level was rejected in a full-access test; no output directory was created. A
normal sandbox could not spawn `fsutil`, so normal tests use an explicit
`pathSafetyProbe` test seam and the real junction test is recorded as a full-access
result. A file symlink test remains environment-blocked by Windows
`EPERM`; this is not reported as path safety having been proven.

This does not claim to eliminate malicious concurrent TOCTOU races or to prove
the absence of every opaque reparse shape. It does refuse a statically present
ancestor link and refuses when the environment cannot prove the check.

## Verification

- Bundle suite: 16 passed, 1 environment-skipped (file symlink) in full access;
  the two real junction cases pass only when the reparse probe is executable.
- Normal-sandbox CLI: no output, exit 2,
  `PATH_SAFETY_PROBE_UNAVAILABLE: ... fsutil unavailable`.
- Full-access CLI: valid single-artifact bundle `ASSEMBLED`, exit 0, manifest
  written; source file unchanged.
- All 27 `tests/v02-*.test.mjs` and the V0.1 entries are re-run after these
  changes; results are recorded in the final report for this work package.
- No dependency was installed, no ACL/profile was changed, and no host or fake
  model was started.
