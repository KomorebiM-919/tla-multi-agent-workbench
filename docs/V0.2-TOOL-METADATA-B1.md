# V0.2 B1: passive tool metadata contract and implementation handoff

Date: 2026-10-21. Reviewed implementation baseline:
`b6c9af132f76d50819f830241e47734b3d016e75`.
Status: **design only; B1 is not implemented or runtime verified**.
This document assigns an offline implementation package, not a host experiment.
Real-host startup authorization remains **zero**.

## 1. Decision and non-goals

B0 can close within its offline scope: opt-in receipts, per-role independent ID
joins, and write-failure handling have targeted independent review. Its
`binding=consistent` is local correlation, not authentication or host execution.

B1 adds a separate, passive, bounded tool-metadata trace. It does not produce
file-byte evidence, test verdicts, task/review lineage, a synthetic protocol, or
any business acceptance verdict. Existing synthetic v2 collector, acceptance
CLI, gate budgets, provider routing and B0 receipts are unchanged.

Use the source audit and capability report under
`docs/handoffs/v0.2-two-person-round1/` as the source boundary. Source-supported
hooks do not establish real member/process coverage. Do not widen the reviewed
budget plugin or its fingerprint to host the observer. A new observer is a
separate candidate and must not be installed in this package.

## 2. Architecture and deliverables

Three separate components, using Node built-ins and existing helpers only:

1. `tools/lib/tool-trace-contracts.mjs`: strict record/report validation, limits,
   correlation keys and side-effect-free stream inspection.
2. `orchestration/tool-observer/`: passive adapter plus bounded trace writer.
   Merely importing it must not subscribe, open files, spawn or inspect a host.
   An explicit factory receives a dispatcher and writer; explicit attach/stop
   owns subscriptions. No profile/package installation or runner activation.
3. `tools/inspect-tool-trace.mjs`: offline CLI over explicitly selected files.
   It validates framing, sequence, pairing and capture health; emits metadata
   diagnostics only. It never calls acceptance-summary or synthetic collectors.

New tests use an invented dispatcher and actual temporary local files. No DSH
modules are imported/executed. Public fixture origin is `simulated-dispatcher`.
A local source-map document must identify audited archive entry/hash/lines for
each mapped field and registration API before an adapter is implemented. If a
field or subscription contract cannot be established, report the gap; do not
invent a host API to satisfy this document. Static source reads are permitted;
dependency installation, host invocation and profile mutation are not.

## 3. Trace framing: tla.tool-metadata-trace/v1

UTF-8 JSONL: exactly one header, zero or more observations, exactly one footer.
Every record has exactly the specified fields; additional fields are rejected.
No BOM, blank interior lines, malformed UTF-8, unpaired UTF-16 surrogates,
unknown record kinds or trailing data after the footer. Missing/partial footer
means `INCOMPLETE`, never a healthy empty trace. An unexpected I/O failure may
leave a partial record; inspection must report it without repairing the file.

Header exact fields:

| Field | Contract |
|---|---|
| schema | `tla.tool-metadata-trace/v1` |
| kind | `header` |
| traceId | fresh canonical lowercase UUID v4 per attachment |
| origin | `simulated-dispatcher` or `host-notification` |
| scope | `tool-metadata-only` |
| bindingClaim | object with exactly runnerRunId, launchId, gateRunId, budgetRunId; each valid B0 ID/UUID or null |
| order | `observer-delivery-only` |
| coverage | `unknown` |

Binding claims are configuration assertions, not observations. B1 never upgrades
them to consistent or verified. All four may be null. A future independent join
must compare trace ownership and receipts; matching strings alone are inadequate.
The header must not contain executable paths, argv, prompt, environment or agent
objects. Origin is a declared capture source, not authenticated provenance.
Do not relabel fake-dispatcher output as host-notification even when a receipt
from another producer is present. No existing consumer may promote this origin
string into hostVerified=true.

Observation exact fields:

| Field | Contract |
|---|---|
| kind | `observation` |
| receiptSeq | positive safe integer, consecutive from 1 in this file |
| source | `tools/result` or `session/event` |
| event | `call` or `result`; tools/result only permits result |
| sessionId, callId, rootCallId, toolName | each bounded identifier string or null |
| sourceSeq | nonnegative safe integer or null; a session-local link only |
| outcome | `success`, `error`, or `unknown`; call requires unknown |
| valueState | `absent`, `present`, or `unknown`; call requires absent |
| process | null, or the exact foreground-pwsh object below |

Identifier strings are nonempty, at most 128 UTF-8 bytes, without control
characters or leading/trailing whitespace. They are opaque, not inferred roles
or filesystem paths. Unknown identity is null; do not fabricate a captain,
member, task or attempt from tool names. If the actual host identity exceeds
this grammar, emit a normalization diagnostic and null, not a clipped ID that
can collide. If toolName cannot be safely represented, use null similarly.

Foreground-pwsh process object exact fields: exitCode (safe integer or null),
signal (bounded identifier or null), timedOut (boolean or null), aborted
(boolean or null), stdoutTruncated (boolean or null), stderrTruncated (boolean
or null). Only project fields actually proven by the source mapping. Background,
persistent and unknown execution paths have process=null. No command, cwd,
stdout/stderr, tests-passed counts or suite hashes are captured. A zero exit is
an observed process fact, not proof of tests passing. A value may be present
without containing any trustworthy process facts. Do not coerce types.

Footer exact fields:

| Field | Contract |
|---|---|
| kind | `footer` |
| traceId | same as header |
| observationsWritten | exact observation count |
| captureState | `finalized` or `degraded` |
| diagnostics | bounded array of the diagnostic objects below |
| diagnosticsDropped | nonnegative safe integer |

Diagnostic exact fields: code (documented fixed enum), receiptSeq (positive
safe integer or null), count (positive safe integer). No free-form exception
text or host data. Initial codes: FIELD_UNAVAILABLE, FIELD_INVALID,
CALL_UNPAIRED, RESULT_UNPAIRED, CALL_IDENTITY_MISSING, CALL_CONFLICT,
RESULT_CONFLICT, SOURCE_LINK_AMBIGUOUS, LIMIT_REACHED, WRITE_FAILED,
SUBSCRIBE_FAILED, UNSUBSCRIBE_FAILED, NORMALIZATION_FAILED.
These may be coalesced by code/receiptSeq. An inspector's parse/I/O diagnostics
use its separate report contract and must not be appended to the original file.

`finalized` means record finalization completed without capture failures known
before the footer was emitted; it is not a durability/handle-close receipt and
does not mean complete host coverage. Missing optional
identity is recorded as FIELD_UNAVAILABLE and leaves coverage unknown; invalid
fields, pairing ambiguity, limits, write/subscription failures cause degraded.
Null identities cannot support a paired result regardless of captureState.
Any diagnostic overflow increments diagnosticsDropped and forces degraded;
discarding diagnostic detail must never erase the fact of capture degradation.

## 4. Correlation and ordering

Assign receiptSeq synchronously when accepting an observation for writing. It is
delivery order only, never physical read/write completion or cross-session
causality. No wall-clock sorting, no conversion to synthetic file index.
Do not add a physical-order claim from tools/result, even for one process.

A pairing key requires non-null sessionId and callId. rootCallId is retained,
never substituted for a missing callId. SourceSeq is not globally unique.
Reusing identical IDs and identical metadata cannot always be distinguished
from replay; the correlation view is not authenticated execution accounting.
Multiple observations from different sources remain separate records; no
cross-source deduplication by callId. The same source/session/call/event may be
an exact replay: count it in raw delivery, report the replay in inspection, and
count it once in the correlation view only when all metadata fields agree
except receiptSeq. A changed replay is a conflict, never last-record-wins.

Pair calls and results only inside the same trace/session/call identity.
Missing calls/results, changed tool names, reused call IDs, competing results
or unsupported source links remain diagnostic. A tools/result observation may
be associated with session/event only when shared identities actually agree;
otherwise keep separate, not falsely deduplicated. Matching nulls never pair.
Stream inspection may resolve a later-delivered matching record; it still
cannot infer physical operation order. Pending correlation must be bounded.

When two result observations share a pairing key, compare all known process
facts as well: exitCode, signal, timedOut, aborted, stdoutTruncated and
stderrTruncated. A known value that differs is RESULT_CONFLICT; null is unknown
and is never treated as the opposite fact. Known values that agree, or
complementary fields where the other side is null, remain valid. Both records
stay in the trace; a conflict is not resolved by keeping the last record.

## 5. Writer lifecycle, containment and privacy

Explicit options: outputFile, maxBytes, maxObservations, maxPending. Defaults:
8 MiB total, 10,000 observations, 1,000 pending correlation keys. User values
must be positive safe integers no larger than defaults. Maximum JSONL record
16 KiB; diagnostics at most 128 entries. Reserve 64 KiB of maxBytes for footer;
maxBytes must be at least 128 KiB. The total includes newline/header/footer.
Limit reached stops further persistence, records degradation if writable, and
does not silently truncate fields or overwrite earlier records.

Use an explicit fresh file under an explicit existing output directory. Refuse
overwrite; use exclusive creation. Reuse the existing path safety checks rather
than writing a lexical-only approximation: unsafe/uninspectable ancestors are
blocked before attachment. No malicious concurrent TOCTOU guarantee is made.
Keep files local/ignored; no automatic public bundle or upload.

Attach must establish the file/header and all supported subscriptions before
reporting attached. Partial attach rolls back subscriptions and marks degraded
if possible. No callback may throw or return a rejecting promise into the host.
Bound synchronous metadata extraction, catch property access/serialization and
I/O errors, never serialize arbitrary tool/agent objects. Avoid asynchronous
unbounded queues; the audited host does not await logging promises. Handle short
writes explicitly. Stop is idempotent: detach listeners, finalize once, close
handles. Never wait indefinitely or kill unrelated processes to finish logging.
Successful footer emission precedes handle close: if close subsequently fails,
stop must return failed/degraded health to its caller and retain that error.
An offline file inspector cannot discover an unrecorded post-footer close
failure. VALID_METADATA therefore certifies file consistency only, not successful
writer shutdown; any future runtime gate must independently retain writer health.

Writer faults latch degraded state and stop persistence. Return an in-memory
health result even when no footer can be written. Partial artifacts remain
untrusted and untouched for diagnosis. The adapter does not change tool return
values, permissions, approval flow, provider routing or request budgeting.

Only metadata in section 3 is permitted. Never store raw arguments/results,
file content/diff, command, stdout/stderr, credentials, environment or prompt.
Do not hash omitted raw content as a workaround. Even IDs/tool names can be
private, so public tests use invented data and raw runtime files stay local.

## 6. Inspector report: tla.tool-metadata-report/v1

Exact top-level fields: schema, scope, status, hostVerified, coverage, origin,
traceId, binding, counts, diagnostics.
- schema=`tla.tool-metadata-report/v1`, scope=`tool-metadata-only`.
- status=`VALID_METADATA` or `INCOMPLETE`; hostVerified=false, coverage=unknown.
- origin/traceId equal validated header values, or null when unavailable.
- binding={status:'unproven', claim:<validated bindingClaim or null>}.
- counts={observations, calls, results, pairedCalls, exactReplays}; all
  nonnegative safe integers for records actually validated before failure.
- diagnostics items={code,receiptSeq,count}; enum includes footer codes plus
  INPUT_INVALID, INPUT_IO_FAILED, HEADER_INVALID, RECORD_INVALID, FOOTER_MISSING,
  FOOTER_INVALID, SEQUENCE_INVALID, TRAILING_DATA, EXACT_REPLAY.

VALID_METADATA requires valid framing, counts, sequence, finalized footer and no
known pairing/conflict or capture faults. Exact replay alone is informational;
FIELD_UNAVAILABLE is informational only if no attempted pairing depends on it.
Otherwise INCOMPLETE. Neither status means coverage or business completion.
No `closed`, `syntheticAcceptance`, file hashes or task verdicts in this report.
Unknown fields are rejected. CLI takes exactly --trace <file> and --out <fresh
report file>; --help is independent. Exit 0 VALID_METADATA, 2 INCOMPLETE or
invalid input, 1 usage/output I/O failure. Input bytes never change. Report
limits and diagnostic coalescing follow the trace limits; input inspection is
streaming/bounded and refuses oversized input rather than reading all first.
Apply the same explicit-path, exclusive-output and ancestor-safety policy to
the CLI report. Output I/O failure must still return a nonzero exit if a report
cannot be written; never overwrite an earlier report to record that failure.

## 7. DSH offline implementation and first-pass self-check

Deliver sections 2-6 together. No B0 runtime plumbing, profile installation,
package manager calls, host startup, new dependencies, synthetic adaptation or
acceptance integration. If source mapping is insufficient, deliver an explicit
unsupported adapter path and identify the missing evidence; do not fake it.

### Host-shaped adapter boundary

`orchestration/tool-observer/host-bridge.mjs` is a separate opt-in layer. It
accepts positional `(exec, result)` and `(session, event)` callbacks and an
explicit `subscribe(eventName, callback) -> disposeFunction`; it does not use
the generic single-payload mapper. It projects only the audited fields
(`exec.callId`, `exec.rootCallId`, `exec.name`, the validated
`exec.agent.session.id` chain, `result.isError`, own `value` presence, the
foreground-pwsh process leaves, and `session/event` call/result fields). Missing
or malformed values stay null/unknown with a safe diagnostic.

`orchestration/tool-observer/context-subscription.mjs` is a thin Cordis-shaped
boundary for a caller-supplied `ctx`: it calls `ctx.on(name, callback)` as a
method, requires a function disposer, never calls `ctx.off`, and passes no
`global`/`prepend` option. It does not discover or import a context and has no
import-time side effects. The publicly documented Cordis/DSH context export and
live member coverage remain unsupported; the `host-notification` origin remains
reserved and is not activated. Async disposers are observed but not awaited:
each item is counted separately, so `asyncCleanupPending` stays true until all
observed items settle; `stop()` returns `ok:false` and `ownershipUncertain` while
work is outstanding. A rejection is caught and latched in
`asyncCleanupFailure` (never erased by a later success), while
`asyncCleanupSettled` becomes true only when every observed item has settled;
the already-returned `ok:false` is not changed. Registration failure rolls back
prior disposers with the same aggregate state; if a callback may have been
retained, the bridge reports `ownershipUncertain` and latches callbacks inert
rather than claiming detachment.

Required counterexamples/positives, executed against final code:
1. Valid invented single-session trace; distinct concurrent sessions and
   out-of-delivery results without asserting physical chronology.
2. Realistic fake dispatcher registration/unsubscription: callbacks do not
   alter original result references or propagate exceptions; stop twice;
   failed subscription rolls back. Import alone has no effects.
3. Both sources observing one call; exact replay vs changed replay; reused call
   IDs across sessions; missing identity; error result without success value;
   orphan results/calls; conflicting source identities; each known process field
   conflicting across sources, null-vs-known, both-null and agreeing positives.
4. Strict schema/type/UTF-8/surrogate/unknown-field checks, sequence gaps and
   duplicates, footer mismatch/missing/partial, trailing records, empty file.
5. Size/event/pending limits at boundary and just over; bounded diagnostics;
   throwing getters, cyclic supplied objects and oversized private data do
   not leak. Secret canaries in omitted fields never appear in trace/report.
6. Actual temporary-file writing plus injected short write, partial write,
   disk error, existing file, footer/close failure. No false successful writer
   health; a post-footer close fault cannot be claimed detectable from file alone;
   original failure retained; no unrelated file removal. Path assertion, open,
   header, observation, footer, subscription and rollback exceptions are all
   treated as untrusted: only a fixed stage/code may escape, never external
   exception text, including externally supplied TraceError instances. Test path
   checks separately and classify environment blocks honestly.
7. CLI actual exit codes; no raw argument/result fields; hostVerified=false and
   unknown coverage in every successful report. No synthetic collector call.
8. Related Phase A/B0 tests plus V0.1 workflow/preflight/claim compatibility.
   Broaden only for actual touched behavior; do not mechanically rerun every
   unrelated suite instead of attacking new failure paths.

Complete a risk-proportionate first-pass self-check before handing back:
counterexamples, positive/boundary cases, actual outputs and exit codes against
final code, final diff/sensitive-data scan/docs consistency. Report failure,
skip and environment block separately; do not promise zero defects. Commit by
topic and ordinarily push verified offline work using standard authentication.
Do not refresh frozen handoff hashes, merge main, force-push or delete retained
raw evidence. Use the final fixed commit in handoff, not a floating HEAD label.

## 8. Gate after implementation

Codex independently reviews contract fidelity and adversarial tests before any
installation proposal. Offline tests authorize no real observer load. A future
host trial needs a separate approved installation/fingerprint plan, full pinned
preflight, fresh run/project, unchanged request ceiling and explicit one-run
authorization. Actual member coverage, shutdown loss and runtime receipt join
remain unverified until then. Exact bytes/concurrent acceptance require a later
design; B1 cannot close V0.2 by itself.

## 9. Design self-check (not implementation test results)

The author checked this design against the audited notification/DTO limitations
and the reviewed B0 implementation. The following are contract walkthroughs,
not tests run against an implemented observer:

| Scenario | Required result / boundary |
|---|---|
| gate receipt exists, DSH never started | no observer activity can be inferred |
| invented trace plus otherwise matching runtime receipts | simulated origin retained; no verified binding |
| successful finalized trace | VALID_METADATA only; unknown coverage, hostVerified=false |
| worker session identity unavailable | null plus diagnostic, no inferred role or successful pairing |
| parallel result delivery reverses completion | retain delivery order; no file chronology or synthetic index |
| two sessions reuse callId | separate keys; never merge on callId alone |
| write fails before footer, tool succeeds | tool value unchanged; trace INCOMPLETE, original fault retained |
| missing result, clean host exit | incomplete correlation; host exit cannot fill the gap |
| partial attach or repeated stop | bounded rollback/close, no duplicate healthy footer |
| private fields contain canaries | omitted, not serialized or hashed |
| optional observer files absent in an old bundle | B0/default consumers unchanged; no history backfill |

During design review the output report's physical-path rules and the limit of
identical-ID replay classification were made explicit. No runtime code changed,
so no implementation or V0.1 test pass is claimed for this documentation-only
delivery. DSH must execute section 7 against its final implementation; Codex
review and separate runtime authorization remain required.
