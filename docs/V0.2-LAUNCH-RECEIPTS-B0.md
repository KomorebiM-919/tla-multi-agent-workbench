# Phase B0 — explicit launch receipts

B0 adds an opt-in local correlation record between the supervised runner and the
gated launcher. It does not add a live observer, a host integration, physical
file truth, or a business acceptance verdict.

## Scope

- `tla.runner-launch-receipt/v1`: written by the supervisor after the child
  **spawn event**, or with `state: "spawn-failed"` after a failed spawn.
- `tla.gate-launch-receipt/v1`: written by the gated launcher before it can
  spawn the host; a receipt write failure refuses the launch.
- Both records use `launchId` (canonical UUID), the runner run ID, the actual
  launcher PID, and a SHA-256 of `JSON.stringify({ command, args })`.
- The gate record adds its own `gateRunId` and `budgetRunId`.
- The runner writes its record under the run directory; the gate writes under
  the same fresh run directory. The gate refuses a receipt path outside that
  directory.

The default is unchanged: `evidenceReceipts` is absent/false and no receipt
arguments or files are produced.

## CLI and spec wiring

```text
node tools/experiment-runner.mjs --spec <spec.json>
```

With `evidenceReceipts: true` in the spec, the runner passes:

```text
--receipt-runner-id <runnerRunId>
--receipt-launch-id <uuid>
--receipt-file <runDir>/gate-launch-<uuid>.json
```

to the launcher. The command generator accepts `--evidence-receipts` for
supervised specs. A direct launcher command is refused because it cannot create
the runner-side record. The launcher's argument parser accepts the three flags
only together and validates the UUID and ID before writing anything.

Exit codes are unchanged. A gate receipt failure is an environment refusal
(exit `2`) before host start. A runner receipt failure after a successful spawn
stops the run and tears down the children; the primary error remains in the
reason even when teardown adds a cleanup diagnostic.

## What the receipt proves

It proves that a particular launcher invocation was started by a particular
runner process and that both sides recorded the same command/argv digest. It is
local, self-produced correlation evidence. It is **not** authentication, not a
proof of a real DSH launch, and not a substitute for independent logs.

The receipt contains no prompt, environment variables, credential values or
raw request bodies.

## Bundle join

`bundle-run-evidence` parses both receipt schemas strictly (exact fields,
canonical UUID, PID/state, lowercase 64-hex digest). It reports:

- one or both receipts missing: `unproven`;
- simulated receipts: `unproven`; simulated data never upgrades a real bundle;
- field/PID/digest/origin mismatch: `INCOMPLETE`;
- matching runtime receipts plus independent runner summary, gate summary and
  budget events with the same IDs: `binding.status = "consistent"`.

Even when consistent, the bundle keeps `hostVerified: false`, scope
`local-artifact-inventory`, and no business `closed` value.

`gateRunId`, `budgetRunId` and the upstream service run ID are different
concepts. The upstream event `runId` is not promoted to a gate ID; it is reported
as `UPSTREAM_ID_SEMANTICS_UNSUPPORTED`. Existing log fields whose semantics are
not frozen remain unproven rather than guessed.

## Tests

- `tests/v02-launch-receipts.test.mjs` — schema strictness, duplicate/extra
  fields, PID/state, digest stability, simulated receipts, missing receipts,
  independent-ID mismatch, consistent join.
- `tests/v02-launch-receipts-producers.test.mjs` — a real local gated-run child
  writes a gate receipt; the runner writes a spawned runner receipt after the
  spawn event; the gate then fails at config probing against a deliberately
  absent DSH path and never launches a host.
- Existing 29 v02 suites, workflow logic, preflight script, claim integration
  and both Python entry points remain green.

No DSH host, model call, fake model service, dependency install, profile or ACL
change was made.

## Limits

The receipt format cannot detect a malicious process that deliberately writes a
matching forged record. It does not prove the child PID was the DSH host (it is
the gated launcher, by design), does not bind to an external observer, and does
not replace Phase B1. Runtime-origin fixtures in tests are invented validation
data, not measured provenance.
