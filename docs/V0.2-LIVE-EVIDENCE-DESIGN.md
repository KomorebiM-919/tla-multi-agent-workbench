# V0.2 real-evidence capture: minimum design and implementation handoff

Date: 2026-10-21. Status: **design only; no live collector implemented**.
Design baseline: `2fc3bc1d6bcd0556c6a62bbb1a03702b8b901f07`.
This is an additive design. It does not change the synthetic protocol, budget,
existing acceptance CLI, experiment spec or any installed profile/plugin.

## 1. Decision

Start with an offline **source capability audit and run-artifact bundle**, not a
live acceptance adapter. Do not invent observer hooks, fill historical gaps or
feed real logs into the synthetic collector by relabeling their origin.

Phase A (assigned to DSH) implements the two contracts below, offline validation
and invented test inputs. It inspects installed source read-only, without loading
plugins or starting DSH. Phase B (Codex decision after audit) chooses a supported
observer implementation. Phase C requires separately approved installation/profile
changes and a separately approved host experiment. None is authorized by this
design or by a passing Phase A report.

The goal of Phase A is to answer precisely which facts can be collected from
which interfaces, and to freeze the bytes actually used in an offline assessment.
An assembled bundle is not proof that its events happened or that closure passed.

## 2. Verified current source facts

References are repository-relative, fixed at the design baseline:

| Fact | Source | Consequence |
|---|---|---|
| runner ID is derived independently | `tools/experiment-runner.mjs`, `deriveEndpoints` | It is not necessarily the gate ID |
| runner does not pass its ID as gate `--run-id` | same file, `buildHostArgs` | Existing launch args do not establish that mapping |
| gate generates an ID and passes `TLA_RUN_ID` to DSH | `tools/gated-run.mjs`, `main` / `buildInvocation` | Budget/host ID can be tied to gate ID, not inferred from runner ID |
| config probe has a separate `-probe` identity | same file, config/invocation binding | Probe and real-host evidence must remain separate |
| budget plugin listens to `agent/request` | `orchestration/interceptor-plugin/index.js`, `apply` | Budget events are not tool or member filesystem observations |
| ledger measures request-stage counts | `tools/ledger-from-run.mjs` / `tools/recompute-ledger.mjs` | Consistent request counts do not prove tool execution |
| existing collector requires synthetic origin and serial-total operations | `tools/collect-run-evidence.mjs`, `collectEvidence` / `orderedOperations`; `docs/EVIDENCE-PROTOCOL-v1.md` | A live stream, overlapping operations or uncertain chronology cannot use this format as proof |

No live tool-event subscription has been verified in this design. Event names in
comments, catalog entries and request schemas do not prove dispatch/completion
hooks. A final team.json is not task history. Policy rule usage is not execution.

JSON examples below show envelope shapes, not passing fixtures; required arrays
and evidence must satisfy the accompanying rules.

## 3. Phase A contract: capability report

Proposed new JSON schema discriminator: `tla.capture-capabilities/v1`.
Required top-level fields (unknown fields rejected):

```json
{
  "schema": "tla.capture-capabilities/v1",
  "scope": "source-audit",
  "hostVerified": false,
  "sources": [],
  "capabilities": [],
  "issues": []
}
```

`sources[]` has exactly `{id, component, productVersion, packageVersion,
containerSha256, entry, entryBytes, entrySha256}`. `productVersion` and
`packageVersion` are strings or null (null means unknown). `component` is `host`
or `agent-teams`; `entry` is a relative archive/package path, not a private
absolute path. `entryBytes` is a nonnegative safe integer; hashes are lowercase
64-hex strings over exact bytes. `containerSha256` is a hash or null when no
single archive is involved. Never treat Electron's version as productVersion.
Keep extraction commands and full raw sources local; do not copy an installed
archive or credentials into the repository.

`capabilities[]` must contain each ID once:
`launch-binding`, `member-call-result`, `task-attempt-lineage`, `read-bytes`,
`write-before-after`, `path-containment`, `test-process-exit`, `causal-order`,
`capture-completeness`.
Each has exactly `{id, status, evidence, limitations}`:
- status: `source-supported`, `unavailable`, or `unknown`;
- evidence: array of `{sourceId, startLine, endLine, symbol, finding}`;
  line numbers are positive safe integers over the exact UTF-8 entry, inclusive;
- limitations: string array, including member scope, concurrency and truncation
  limitations when relevant. Evidence references must resolve to sources.

`source-supported` requires concrete code showing payload, dispatch and result
delivery, scope (including member contexts), and how errors propagate. Mere type
declarations or event-name search hits are insufficient. The tool validates an
analyst-authored report against explicitly supplied source entries; it does not
infer semantic support from grep hits. A human/independent code review must
validate the findings before Phase B. A source-audit result
cannot claim runtime-verified coverage. `unknown` is a valid audit result, not a
license to invent an API or to mark the run closed.

`issues[]` uses `{code, capabilityId, detail}`; capabilityId may be null. Missing
required capabilities, contradictory entries or invalid locators are issues.
The validator checks locator structure/references; a source audit reviewer must
also check the referenced source bytes and semantics. Hashes are not signatures.

## 4. Phase A contract: run-artifact bundle

Proposed discriminator: `tla.run-evidence-bundle/v1`. Required fields:

```json
{
  "schema": "tla.run-evidence-bundle/v1",
  "scope": "local-artifact-inventory",
  "hostVerified": false,
  "status": "INCOMPLETE",
  "binding": {
    "runnerRunId": null,
    "gateRunId": null,
    "budgetRunId": null,
    "status": "unproven",
    "evidenceRefs": []
  },
  "artifacts": [],
  "issues": []
}
```

`artifacts[]` entries have exactly `{id, role, path, bytes, sha256}`.
Allowed roles: `runner-summary`, `launch-receipt`, `gate-summary`, `gate-events`,
`budget-events`, `upstream-events`, `observer-events`, `capture-capabilities`.
IDs are unique nonempty strings <=128 characters. Inventory ID fields must
be nonempty strings <=128 characters or null where explicitly allowed; flags
must be booleans, not coerced strings. Unknown fields/schemas are rejected. Paths are unique canonical
project-independent bundle-relative paths. No absolute, drive, UNC, device,
traversal, dot-segment, alternate-stream or reserved-device paths; no symlinks,
junctions or other unresolved reparse paths. Reuse established validation where
applicable, but do not claim lexical containment proves physical containment.

Read caller-selected local source files only. Stable assembly must compare
before/after metadata and hash the exact copied bytes, publish the manifest last
in a newly created output directory, and never modify source inputs. Reject
observable changes during capture; this is not protection against a malicious
local writer or a TOCTOU-free filesystem snapshot. If physical path safety cannot
be established in the execution environment, reject that input. Do not fall back
to path accessibility for opaque Global reparse shapes.

Initial limits: at most 32 artifacts, 8 MiB per artifact, 64 MiB total copied
bytes, 1 MiB manifest JSON, 32 JSON nesting levels. Limits are refusal conditions,
not truncation policies. Duplicate roles for distinct valid artifacts are allowed.
Separate content digests from private original-path mappings kept outside the
publishable bundle. Raw bundle contents remain local, ignored and uncommitted;
invented fixture bytes are used for public tests. Do not assume log files are
safe to publish merely because the manifest contains hashes.

`status` is `ASSEMBLED` or `INCOMPLETE`. ASSEMBLED requires at least a runner
summary plus verified inventory hashes and successful assembly, not complete
business evidence. No `closed`, `acceptance` or `verdict` field is allowed.
Missing host/observer facts can remain issues even for an assembled inventory.
Invalid input/unreadable bytes cannot yield ASSEMBLED.

Binding status is `consistent` or `unproven`. IDs remain null when unknown.
`evidenceRefs` contains artifact IDs. CLI expected IDs must not themselves become
evidence. Existing runner/gate files with coincident timestamps are insufficient
to prove the parent-child mapping. Phase A must retain `unproven` unless an actual
launch receipt independently records both IDs and the created child identity.
Gate and budget IDs must match when both observed; conflicts make INCOMPLETE.
Every inventoried run-bearing artifact must be checked for conflicting run
identity; a selected receipt cannot excuse other-run artifacts in the bundle.
Multiple contradictory runner summaries must also be rejected. Missing IDs stay
unproven; they must not be filled from the selected receipt without observation.
An observer ID cannot be inferred from a request correlation ID.

Proposed receipt (not yet implemented): runner records its generated ID and the
exact child launch; gate records the received runner ID plus generated gate ID
and budget/host identity. Join on the explicit launch reference, and preserve
both original records and hashes. PID alone is insufficient because of reuse.
Installation UUIDs/timestamps are not substitutes. Implementing this receipt
requires a later Codex-approved runner/gate change; Phase A must not synthesize it.
Even a consistent local receipt is provenance against accidental mixing, not
authentication against local processes that can edit both files.

`issues[]` uses `{code, artifactId, detail}`; artifactId can be null. Include
missing mapping, observer data and source conflicts without fabricating zeros.

## 5. Facts required before a live adapter can be designed

| Fact | Required physical/host evidence | Insufficient substitute |
|---|---|---|
| Member call/result | stable session + call identity, exact success/error/completeness, member path audited | captain transcript or descriptor |
| Task lineage | task/attempt owner and successful transitions; explicit review target/source rejection | subject regex or final task snapshot |
| Read bytes | bytes actually delivered for a full-file read, with operation identity | rendered numbered text or later disk hash |
| Write bytes | exact pre/post bytes for that write, observed success, path identity and race limitations | input content plus final project snapshot |
| Test history | member tool process command/cwd/exit and complete stdout; exact suite bytes | text containing 0 failed or collector's later test |
| Ordering | producer-origin start/end causal facts across every relevant session | log arrival order, wall clock or per-session seq |
| Completeness | start/end capture markers, declared coverage, dropped-event/error detection | empty log or process exit 0 |

No wrapper may re-execute a member operation just to manufacture evidence.
Filesystem polling cannot prove transient writes. Full bytes, encoding and CRLF
must be preserved; partial/redacted/truncated bytes cannot prove equality.

Live concurrency is likely incompatible with v1's serial-total requirement.
Do not sort receipt timestamps into invented authoritative indices or serialize
the host without separate review. Phase B must choose either a verified serial
capture mode or a new partial-order protocol and evaluate conflicting writes.
Do not modify v1 acceptance semantics merely to ingest a trace.

## 6. Phase A implementation package for DSH

Suggested independent files: `tools/audit-capture-capabilities.mjs`,
`tools/bundle-run-evidence.mjs`, dedicated tests and contract documentation.
Names are suggestions; discriminators and trust boundaries above are normative.

1. Read installed host/team sources without running imports, dump-config,
   registration, package installation or host CLI. Audit exact current bytes and
   versions. If an archive reader is unavailable, report the capability unknown;
   do not install a dependency. Reference only relevant source entry ranges.
2. Implement strict offline report validation and explicit bundle assembly. The
   audit CLI accepts an analyst-authored report and an explicit source-ID-to-file
   mapping; it verifies entry hashes/bytes/locators without executing source. The
   bundle CLI accepts an explicit local selection file (artifact ID, role, source
   path, desired relative output path), optional expected IDs used only for
   comparison, and a fresh output directory. Local selection/source-map files
   contain private paths and must never be published. No
   auto-discovery of profiles, credentials, unrelated logs or the user's home.
3. CLI exits: 0 valid capability report / assembled inventory, 2 invalid or
   incomplete data, 1 CLI or I/O failure. A report containing unknown capabilities
   may validate successfully; output scope and limitations must remain explicit.
   Zero must never be described as readiness or live acceptance. If failure and
   environmental trouble coexist, preserve both diagnostics without replacing the
   original result. This is separate from migration test exit conventions.
4. Public tests use invented files for assembly/hash/parser/path tests, not logs
   copied from real runs. Test source mutation, missing/oversized files, malformed
   JSON, duplicate IDs/paths, symlinks/reparse paths, output refusal, copied-byte
   mismatch, ID conflict, missing receipt, unknown member hooks, partial capture,
   CRLF/LF distinction and unknown schemas. Valid partial knowledge must remain
   explicitly unknown, not acquire invented binding or event facts.
5. Preserve old CLI/schema outputs, ten acceptance conditions and V0.1 behavior.
   No integration into summariseRun or collectEvidence during Phase A. Do not
   refresh the old frozen handoff core-file hashes.
6. Self-check requirements, counterexamples, compatibility, actual exits,
   cleanup ownership, sensitive information and docs before handoff. Run focused
   checks and a final affected regression pass; distinguish environmental blocks
   from assertion failures, and do not repeatedly rerun unrelated green suites.

Codex reviews the capability audit and chooses the critical observer, ordering,
byte provenance and binding design. DSH owns Phase A implementation, tests and
documentation. Future installation/profile changes, native helpers, hooks and
host experiments need their own authorization. Real-host startup authorization
remains zero. This document adds no installed plugin or Skill.
