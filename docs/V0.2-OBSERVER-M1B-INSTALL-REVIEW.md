  remains a configuration-synthesis check, not mount proof.

## 5. Observer patch (12 fields)

The gate writes the patch only after its real `gateRunId` exists and the runner
receipt's `runnerRunId`/`launchId` are available:

```text
enabled, runDir, traceFile, lifecycleFile,
runnerRunId, launchId, gateRunId, budgetRunId,
maxBytes, maxObservations, maxPending, cleanupTimeoutMs
```

`gateRunId` and `budgetRunId` are the gate's actual run ID; an upstream service
ID is never substituted. No raw overlay text, caller-supplied gate IDs,
`global:true` or `prepend` is accepted. The observer is default-off; absent
`observer` in the spec keeps the existing behavior.

## 6. Minimal policy and budget

The proposed probe policy has one captain session: read `probe.txt`, then a
single successful foreground `pwsh` command that prints a fixed marker, then
stop. Any tool error or unexpected request terminates the attempt without retry.
The model-request cap remains the existing `<= 40`; the observer adds no
provider, retry or budget exception. The mount-probe is a separate check and
must not be counted as business acceptance.

## 7. Backup, rollback and approval

Before a future install, record destination absence/path/hash and back up the
new profile's manifests, lockfile and link metadata locally (never credentials).
Rollback removes only the newly created profile link/envelope and restores those
local manifests; it does not delete historical experiments or the budget plugin.

The following still require explicit human approval and are **not** performed by
this offline package:

1. creating the real experiment parent/profile;
2. writing the envelope and internal links;
3. starting DSH, the fake upstream or any model call;
4. accepting a live mount probe as host verification.

## 9. Correction round: evidence consumption and package fidelity

- The mount-probe checker now reads the production lifecycle reader, the B1
  trace contract (`event=result`, separate `source`), both B0 receipts, the
  independent runner/gate summaries, budget events and the ledger output. It no
  longer accepts a caller-provided `binding`, phase array or cleanup boolean.
- Missing material is `incomplete`; contradictory material (identity, failed
  tool, footer, truncation, diagnostics, unsafe DTO) is `failed`. Simulated B0
  receipts keep `binding=unproven`; no synthetic record can set
  `binding=consistent` or `hostVerified=true`.
- `tla.run-ledger/v2` does not carry runner/gate IDs; ledger completeness is
  checked, but ledger-to-receipt identity remains a documented limitation.
- The envelope's root `package.json` is LF-pinned in `.gitattributes` and is no
  longer skipped by blob comparison. The checker verifies manifest bytes, the
  sourceBase Git blob, a fresh `autocrlf=true` checkout and `git archive`, then
  assembles and imports the independent 12-file closure.
- The actual gate path is exercised with a local stand-in: the gate creates the
  receipt, generates its real gate/budget ID, writes the observer patch and then
  refuses before a host starts when the stand-in config probe fails. This is not
  a host mount; a future real attempt must repeat it with the installed bytes.
- The probe policy declares `modelRequests=3` (three sequential captain
  responses), under the unchanged `<=40` cap. `rules.length` is not used as a
  request budget.
