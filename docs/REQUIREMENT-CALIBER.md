## 2. 统一口径提案（按"调用方式"分层）

核心规则只有一条：**先写清是哪一类调用、哪个输入，再写该调用的期望值；同一类调用、同一输入，只允许一个期望值。** 不同调用方式可以有不同期望，但不得把它们写成对同一次调用的互斥期望。

### 2.1 调用方式与适用约束

| 调用方式 | 输入来源 | 标准输出 | 返回值 | 适用约束 |
| --- | --- | --- | --- | --- |
| CLI（`python text_stats.py <文件>`） | 文件路径 | **恰好 4 行** `<key>: <value>`，顺序 `char_count`、`line_count`、`non_empty_line_count`、`word_count` | 进程退出码 0 | BC-12、AC-12（第一条） |
| CLI（`python text_stats.py`，stdin 无重定向） | 标准输入 | 同上一行（有输入时） | 退出码 0 | BC-12 |
| CLI（`python text_stats.py`，stdin 被重定向为空） | 空标准输入 | 4 行、四项全为 0 | 退出码 0 | BC-12；**已裁定**：`docs/REQUIREMENT-BASELINE.md` 的 RB-2（原待确认项 P-2） |
| 程序化注入（`main(argv, stdin_text=...)`，显式传入非空或空串） | 参数注入 | **不写任何流** | 返回整数退出码 | AC-12（第二条）；**已裁定**：RB-1（`True 0 int` 是外层 `print` 的输出，见 2.4） |
| 程序化注入（`main([...])`，未传 `stdin_text`） | 文件路径 | 不写标准输出 | 返回整数退出码 | 与上一条相同 |
| `--help` | — | argparse 帮助文本 | 退出码 **0** | AC-13 |
| 错误路径（文件不存在/不可读、编码名非法、位置参数多于 1 个） | — | stderr 一行以 `error: ` 开头 | 退出码 **1**（不得沿用 argparse 默认的 2） | AC-13、既有缺陷 b |

即：**"成功输出格式（4 行）"只约束 CLI 路径；"不打印"只约束显式注入输入的编程调用。** 两者作用域不同，AC-12 与 BC-12 不再互斥。

（"4 行格式与字段顺序"、"错误路径退出码 1 / `--help` 返回 0"这两行本身**不在**已裁定的六项口径内，属未逐条裁定的条文，清单见 `docs/REQUIREMENT-BASELINE.md` 第 5.1 节。）

### 2.4 澄清：`main` 自身的输出 ≠ 外层 `print` 的输出

- **`main` 自身**：显式注入输入时不写任何流，只返回整数退出码（已裁定：RB-1）。
- **外层命令**：`python -c "import text_stats as t; code = t.main([], stdin_text=''); print(callable(t.main), code, type(code).__name__)"` 的 stdout 恰为 `True 0 int`——`True`、`0`、`int` 三个值由**外层 `print`** 写入，`main` 贡献的只是返回值 `0`。
- 所以 AC-12（第二条）的"标准输出为 `True 0 int`"与第六轮 `AC-10` 的"标准输出为空"说的是同一事实的两面（前者是外层命令、后者是 `main` 自身），并不矛盾。`main` **不得**去打印 `True 0 int`，也不得打印那 4 行。

### 2.2 行边界集合（BC-02 与 BC-03 的统一）

**行边界集合 = { LF (`\n`)、CRLF (`\r\n`)、CR (`\r`) }，仅此三种。**

- 归一化：先把 `\r\n` 替换为 `\n`，再把剩余的 `\r` 替换为 `\n`（与 Python `io` 通用换行一致）。
- `U+2028`、`U+2029`、`\x0b`、`\x0c`、`\x1c`、`\x1d`、`\x1e`、`\x85` **一律不是行边界**，只算普通字符。
- 因此 `str.splitlines()` **不能**作为 `line_count` 的唯一实现依据（它把 `U+2028`/`U+2029`/`\x0b`/`\x0c`/`\x85` 等也当换行）；BC-03 的判定改为"按上面的行边界集合切分"，并把它的示例值作为该集合下的期望值。
- 切分规则：末尾的换行不产生额外空行 —— `'' → 0`、`'\n' → 1`、`'a\n' → 1`、`'a' → 1`、`'a\nb' → 2`、`'a\n\n' → 2`、`'hello world\nfoo bar\n' → 2`、`'hello world\nfoo bar\n\n' → 3`。
- 仅含空白字符的行**仍然是行**：`'  \n\t\n' → 2`（两行都是空白行），其 `non_empty_line_count` 为 0；**不得把末尾换行之后的空片段另计为一行**（第四次运行中 Requirement Agent 曾把该输入写成 3 行，与上面的规则互斥；该示例现已显式写入演示需求的权威口径）。

### 2.3 由此得到的结论

- AC-12 与 BC-12 的冲突**可以被消除**，且不需要改动任何一个具体期望值：只需把"是否打印"绑定到调用方式。
- BC-03 与 BC-02 的冲突**可以被消除**：把 BC-03 的实现依据从 `str.splitlines()` 改为"2.2 的行边界集合"，其余示例值全部保留（结论值不变）。
- 这两个消除办法都**不是**原文本唯一推出的：原文本同时存在两种自洽解释（见第 3 节），所以下列条目必须由人确认。
