## 2. 条款（R-01 – R-37）

编号规则：`R-xx` 是本稿的唯一引用号；括号内注明来源状态。示例值都是**唯一期望值**——同一输入不允许出现第二种期望。

### G1 接口与调用方式

- **R-01**（已批准，RB-1）显式传入 `stdin_text`（含空串 `""`）时，`main(argv, stdin_text=...)` **只返回整数退出码**：不写 stdout、不写 stderr、不读进程标准输入。
  - 示例：`main([], stdin_text="")` → 返回 `0`，屏幕无任何输出。
  - 示例：外层命令 `python -c "import text_stats as t; code = t.main([], stdin_text=''); print(callable(t.main), code, type(code).__name__)"` 的 stdout 恰为 `True 0 int`——三个值由**外层 `print`** 写出，`main` 只贡献返回值。
- **R-02**（已批准，RB-2）命令行调用、未给出路径、进程标准输入立即 EOF 时走**成功路径**：恰好 4 行、四项全 `0`、退出码 `0`、不阻塞。
- **R-03**（建议维持现状）提供纯函数 `count_text(text)`：接收已解码文本，不读文件、不读流、不做解码；返回**恰好四个整数键** `char_count` / `line_count` / `non_empty_line_count` / `word_count`，不返回额外键。
- **R-04**（建议维持现状）提供 `main(argv=None, stdin_text=None)` 与 `if __name__ == "__main__": sys.exit(main())`；`argv=None` 表示取 `sys.argv`。
- **R-05**（建议维持现状）两类调用**分别适用**、不得合并：命令行调用（`stdin_text is None`）成功时要写 4 行；程序化注入调用要静默。既不允许"程序化调用也打印 4 行"，也不允许"命令行调用静默"。（这条分层本身来自已批准的 RB-1 + RB-2，本稿只是把它写成一条不合并的约束。）

### G2 输出格式与成功路径

- **R-06**（建议维持现状）命令行成功路径在 stdout 写**恰好 4 行**，顺序固定：`char_count`、`line_count`、`non_empty_line_count`、`word_count`；每行 `<名称>: <整数>`，名称为小写下划线分隔，数值为十进制字面量（无引号、无千分位、无前导零、无正号），行尾为单个 LF，不输出其他内容。
  - **换行口径（本稿新增说明）**：实现以 LF 分隔这 4 行；在 Windows 上 Python 文本模式的 `sys.stdout` 会把 LF 转成 CRLF 写出，这属于**宿主换行转换**，不视为违反本条款。验收断言应以"按行切分后的 4 行内容"为准（`splitlines()` 后比较），不得把"Windows 下字节里出现 CRLF"判为失败。
  - 示例：`python text_stats.py sample_input.txt` → 退出码 `0`，输出 `char_count: 20` / `line_count: 2` / `non_empty_line_count: 2` / `word_count: 4`。
  - 示例：`printf 'hello world\n' | python text_stats.py` → `12 / 1 / 1 / 2`。
- **R-07**（建议维持现状）命令行给 PATH 时读该文件，未给 PATH 时读进程标准输入；两条路径都必须得到**完全相同的四项数值**（同一份原始字节）。
- **R-08**（建议维持现状）读文件保留原始换行（`open(..., newline="")` 或二进制后解码），归一化只在 `count_text` 一处完成。
- **R-09**（建议维持现状）stdout 只放那 4 行；错误信息只进 stderr。

### G3 错误路径与退出码

- **R-10**（建议维持现状）以下情形一律以退出码 **`1`** 结束，stderr 至少一行以 `error: ` 开头，不得出现 traceback，不得用 argparse 默认的 `2`：
  文件不存在；文件不可读或是目录；解码失败（非法 UTF-8 字节）；`--encoding` 编码名非法；位置参数多于 1 个。
  - 示例：`python text_stats.py missing-file.txt` → 退出码 `1`，stdout 空，stderr `error: ...`。
  - 示例：`python text_stats.py a.txt b.txt` → 退出码 `1`（不是 `2`）。
- **R-11**（建议维持现状）`--help` 以退出码 `0` 结束，stdout 给出用法（含 PATH 与 `--encoding` 说明）。
- **R-12**（建议维持现状）错误信息正文措辞与语言**不作逐字要求**，只要求 `error: ` 前缀、单行可读、无 traceback。
- **R-13**（建议维持现状）程序化调用（R-01）中若给了非法 PATH 或非法 `--encoding`，仍按错误路径处理并返回 `1`；注入的 `stdin_text` 在这类调用里被忽略（一次运行不可能既成功又如所给路径失败）。
- **R-14**（建议维持现状）不得使用 `sys.exit` 以外的自定义退出码（成功 `0`、受控错误 `1`）。

### G4 文本归一化：BOM 与换行

- **R-15**（建议维持现状）归一化顺序**固定**：① 剥除**一个**前导 `U+FEFF`；② 所有 `\r\n` → `\n`；③ 剩余所有 `\r` → `\n`。此后只按 `\n` 切分。
- **R-16**（已批准，RB-4）换行边界**只有** LF、CRLF、CR 三种。`U+2028`、`U+2029`、`\x0b`、`\x0c`、`\x1c`、`\x1d`、`\x1e`、`\x85` **不是**换行，它们留在行内容里并计入 `char_count`。**不得**以 `str.splitlines()` 作为 `line_count` 的唯一实现依据。
  - 示例：`'a' + U+2028 + 'b'` → `line_count 1`、`char_count 3`。
- **R-17**（建议维持现状）BOM 只剥一个：`'\ufeffabc'` → `char_count 3`；`'\ufeff\ufeffabc'` → `char_count 4`。
- **R-18**（建议维持现状）其它字符（含全角空格、不换行空格）一律不改写，不折叠、不去尾、不 trim 整篇。
- **R-19**（已批准，RB-3）**不做** Unicode 归一化（NFC/NFD 都不做）。

### G5 字符数、行数、非空行数

- **R-20**（建议维持现状）`char_count` = 归一化后文本的 Unicode 码点数（`len(str)`），不按字节、不按字形簇、不按显示宽度。
  - 示例：`'hello world\nfoo bar\n'` → `20`；`'a\r\nb'` → `3`；`'caf\u00e9'` → `4`；`'cafe\u0301'` → `5`。
- **R-21**（已批准，RB-6 + RB-4 示例值）`line_count` = 按 R-15/R-16 切分后的行数；空文本 `""` → `0`；末尾换行**不**产生额外空行；仅含空白的行仍算行。
  - 示例：`""→0`、`"\n"→1`、`"a\n"→1`、`"a"→1`、`"a\nb"→2`、`"a\n\n"→2`、`"hello world\nfoo bar\n"→2`、`"hello world\nfoo bar\n\n"→3`、`"  \n\t\n"→2`。
- **R-22**（已批准，RB-6）`non_empty_line_count` = 对**同一批**切分出的行逐行 `strip()` 后仍非空的行数；行数与非空行数必须出自同一次切分。
  - 示例：`"  \n\t\n"` → `line_count 2`、`non_empty_line_count 0`；`"a\n\n"` → `2` / `1`。
- **R-23**（建议维持现状）空白集合 = Python `str.strip()` 的默认集合（含空格、`\t`、`\x0b`、`\x0c`、`\u00a0`、`\u3000` 等），不扩展、不缩减。
- **R-24**（已批准，RB-3）`'cafe' + U+0301` 只允许 `word_count 1`、`char_count 5`；把它断言成 `2` 属错误（任何版本都不允许）。

### G6 单词规则

- **R-25**（建议维持现状）`word_count` = 正则 `[A-Za-z]+(?:[-'\u2019][A-Za-z]+)*` 在归一化文本上的匹配个数；只有 ASCII 字母是单词字符。
  - 示例：`"hello world"→2`、`"Hello hello HELLO"→3`（不归并大小写）、`"well-known"→1`、`"don't"→1`、`"it\u2019s"→1`、`"a-b-c"→1`、`"hello--world"→2`（连续两个连接符不连接）。
- **R-26**（建议维持现状）数字与下划线**不是**单词字符，会切开字母片段：`"123 456"→0`、`"abc123"→1`、`"a1b"→2`、`"a_b"→2`、`"foo_bar baz"→3`。
- **R-27**（建议维持现状）非 ASCII 字母与组合记号既不是单词字符也不是连接符：`"caf\u00e9"→1`、`"caf\u00e9-mocha"→2`、`"cafe\u0301"→1`。
- **R-28**（建议维持现状）连接符两侧必须紧邻 ASCII 字母：`" -abc"→1`、`"abc- "→1`、`"'abc"→1`。

### G7 编码

- **R-29**（建议维持现状）默认按 UTF-8 解码；既有选项 `--encoding NAME` 覆盖之，语义不变（不新增短选项、不新增其它编码能力）。
- **R-30**（建议维持现状）编码名校验用 `codecs.lookup`；非法编码名 → 退出码 `1` + `error: ` 一行；文件解码失败同样如此。BOM 按 R-17 处理（UTF-8 BOM 解码为 `U+FEFF` 后剥除）。

### G8 依赖与目录边界

- **R-31**（建议维持现状）实现与测试**只允许 Python 标准库**（`argparse`、`codecs`、`re`、`sys`、`io`、`contextlib`、`subprocess`、`unittest` 等）。
- **R-32**（建议维持现状）交付目录固定 `examples/text-stats`，交付文件为 `text_stats.py`（同目录可含 `test_text_stats.py`、`README.md`、`sample_input.txt`）；不新建交付目录，不改仓库根的工作流脚本、编排脚本与 `agents/` 规范文件。
- **R-33**（建议维持现状）不得新增 `requirements.txt` / `pyproject.toml` / `setup.py` / `Pipfile` 等依赖声明；不写交付目录之外的路径；无网络访问、不读凭据。

### G9 示例与样例文件

- **R-34**（建议维持现状；是否固化为不可改由 Q2 决定）`examples/text-stats/sample_input.txt` 内容固定为 `"hello world\nfoo bar\n"`（20 字节，LF 结尾），README 中 `char_count: 20 / line_count: 2 / non_empty_line_count: 2 / word_count: 4` 必须与之逐字自洽。
- **R-35**（建议维持现状）README 中每条可复制示例（文件示例与标准输入示例）的命令与四个数值必须与 R-01 – R-33 逐一自洽，第三方照抄即可复现；不得保留与规则矛盾的历史数值（例如把 `"  \r\n \r\n"` 的 `char_count` 写成 `6`——正确值是 `5`）。
- **R-36**（建议维持现状）描述连接符时不得出现裸的 `U+2019` 字符，必须写成可辨认形式（`\u2019` 转义或明确标注码点）。

### G10 冲突处理

- **R-37**（已批准，RB-5）同一调用方式、同一输入只允许一个期望值。若需求条文之间（含 AC 与 BC 之间）出现互斥期望，**不设隐式优先级**：实施者不得自行选边，必须报出冲突并停止，等待人工裁定。
  - 编排层门禁（已实现）：任一阶段报告 `requirement_conflicts` 非空 ⇒ 立即停止；需求阶段自检报冲突 ⇒ 不启动 Coding Agent。
