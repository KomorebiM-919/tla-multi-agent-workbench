# 勘误：BC-07 跳过说明中的错误需求引文

本文件修正 run 6 独立复核脚本在"跳过 BC-07 单独 `\r`"一段里印出的**错误需求引文**。
两个被引用的已冻结文件（`orchestrator-verification-run6.py`、`orchestrator-verification-run6-output.txt`）
**保持逐字节不变**——它们的 sha256 已写入 `README.md` 与 e3c27c1 审查材料包
（`MANIFEST.md` / `SHA256SUMS.txt`），改一个字节就会让那份已交付、已被独立复核的材料包对不上。

## 一、错误原文（逐字引用）

`orchestrator-verification-run6-output.txt:139-140`（同一段在 `:399-400` 的汇总里重复；脚本侧为
`orchestrator-verification-run6.py:449-453`）：

```
SKIP BC-07 :: 需求只规定“行边界字符先归一化”，未规定归一化后如何单独观测 \r 是否属于 str.strip() 空白；'\r\n' 经 BC-04 归一化后只剩一个行边界，无法把 \r 单独取回，故不构造检查项。
     需求原文: BC-07 的非空行判定必须使用 str.strip() 自身的空白集合，不得扩大也不得缩小；不得把 U+00A0、U+3000 等 Unicode 空白当作可剥离空白，也不得只把 ASCII 空格当作空白。
```

三处错误：

1. **那条"需求原文"不是 BC-07 的原文，而且语义相反。** BC-07 明确把 `\u00a0`、`\u3000` 算进
   `str.strip()` 的空白集合；引文却说"不得把 U+00A0、U+3000 等 Unicode 空白当作可剥离空白"。
2. **归一化顺序被错挂到 BC-04。** `\r\n` → `\n`、单独 `\r` → `\n` 的顺序规则是 **BC-02**；
   **BC-04** 是空文本口径（`""` 四值全 0、不产生任何行）；行边界集合是 **BC-01**。
3. **计数说法不准确。** BC-07 列出的空白字符共 8 个（空格、`\t`、`\n`、`\r`、`\x0b`、`\x0c`、`\u00a0`、`\u3000`）：
   脚本对其中 6 个各做了显式 PASS（输出 `:133-138`），`\n` 由行切分隐含覆盖（行内容不可能含 `\n`），
   `\r` 才是那个跳过项——因此不能笼统写成"其余 6 个空白字符均已实际检查"。

## 二、需求原文（逐字，来源 `requirement.json` → `result.boundary_conditions`）

- **BC-01** 行边界集合（权威口径）：只有 LF(`\n`)、CR(`\r`)、CRLF(`\r\n`) 三种序列构成换行；
  U+2028、U+2029、`\x0b`、`\x0c`、`\x1c`、`\x1d`、`\x1e`、`\x85` 一律不构成换行，它们保留在行内容中并计入 char_count。
  判定方式：以 `"a" + c + "b"` 构造输入，line_count 必须为 1；不得把 `str.splitlines()` 当作唯一实现依据
  （它会把 U+2028/U+2029 等当作换行）。
- **BC-02** 归一化顺序（唯一顺序）：先剥除一个前导 U+FEFF，再把所有 CRLF 替换为 LF，最后把剩余的全部单独 CR 替换为 LF；
  此后只按 LF 切分。顺序颠倒或漏掉单独 CR 的处理都会改变 char_count 与 line_count。
- **BC-04** 空文本：`""` 的 char_count == 0、line_count == 0、non_empty_line_count == 0、word_count == 0；
  空文本不产生任何行（把它记成 1 行属错误）。
- **BC-07** 空白定义：判定 non_empty_line_count 时使用 Python `str.strip()` 的空白集合
  （含空格、`\t`、`\n`、`\r`、`\x0b`、`\x0c`、`\u00a0`、`\u3000` 等），不做自定义扩展也不做缩减。

同一份输出在 `:340` 已经印出过 BC-07 的**正确原文**（`BC-07 covered skipped: …`），
错的是 `:139-140` 那条跳过理由与它的"需求原文"引用。

## 三、结论是否受影响：不受影响

- **跳过本身成立，只是理由写错了。** BC-07 的口径没有"未规定"之处；真正无法单独观测的是
  *"`\r` 是否被 `str.strip()` 视为空白"* 这一事实——因为 BC-02 要求在切分前把所有 CRLF 与单独 CR
  归一化成 LF，任何一行内容里都不可能保留 `\r`，这一条在可观测输入上永远不会被触发，故只标注跳过、不猜。
- 该跳过项在 280 项检查里始终只占 1 项、标为 `SKIP`（不计入 PASS）；BC-07 的可观测部分
  （`:133-138` 六个字符各一项、`:141-142` 的 `'\xa0x\n'` 两项）与正确原文（`:340`）都在同一份输出里。
- 因此 `280 项检查 / 0 失败 / 1 跳过` 的结论不变，`docs/evidence/v0.1-second-run/ACCEPTANCE-STATUS.md`
  第 7 节里对应的中文表述已按本勘误改写。
