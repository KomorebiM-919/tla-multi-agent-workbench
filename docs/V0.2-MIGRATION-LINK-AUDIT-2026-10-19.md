# V0.2 迁移链接审计（2026-10-19）

本文件记录 `git worktree move` 之后发现的**工作区之外**活动引用，以及隔离 profile 的修复与验证。
结论先行：Git 迁移成功，但隔离 DSH profile 的插件链接仍指向已不存在的旧工作树；该链接已按
“profile 内副本 + profile 内链接”修复，完整离线预检通过。宿主实验启动授权仍为 **0**。

## 1. 为什么 Git 干净不等于迁移完成

迁移只改写了 Git 的 worktree 登记。以下对象不在工作区里，Git 不会碰它们：

- 隔离 DSH profile 的 `package.json` 依赖声明；
- `pnpm-lock.yaml` 中该依赖的 `specifier` / `version`；
- `node_modules/<plugin>` 的 Junction（重解析点）。

旧链接的 Target 是 `<repo>\tests\.scratch\v02-worktree\orchestration\interceptor-plugin`。
`v02-worktree` 被 move 走后，该 Target 不存在，链接成为断链。

## 3. 第一次修复为什么还不够

先把 Junction 改指 `<workspace>\orchestration\interceptor-plugin` 后，静态检查通过，但配置合成失败：

```text
config FAIL coverage:launcher-classifier — launcher sees guarded [llm-deepseek], unknown [tla-prelaunch-budget]
config FAIL identity:per-instance — tla-prelaunch-budget → tla-prelaunch-budget (identity-unreadable)
config FAIL identity:no-conflict-or-duplicate — PLUGIN_NOT_VERIFIED (tla-prelaunch-budget)
EFFECTIVE CONFIG FAILED
```

根因在 `tools/gated-run.mjs` 的 `verifyPluginIdentities`：它把 `node_modules/<name>` 解析为真实路径，
并要求该路径位于 profile 根下；工作区在 profile 外，因此 `insideProfileRoot=false`，身份核对拿到
`pkgDir:null`，报 `identity-unreadable`。静态检查直接对目录做指纹，所以出现“静态过、配置不过”。

**没有放宽身份门禁。** 改为在 profile 内放一份与已审查源码字节一致的副本：

- 副本目录：`<dsh-home>\profiles\stage1\vendor\interceptor-plugin`；
- 版本 `0.0.0-local`，3 个文件，`buildDigest=54f1a8e32f717f52d563ba368713c744c3bde486afeb3f3d133052a0a027e43d`，
  与 `orchestration/gate/preflight.mjs` 的 `REVIEWED_PLUGIN_EVIDENCE` 及工作区源码一致；
- profile `package.json`：`link:./vendor/interceptor-plugin`；
- `pnpm-lock.yaml`：`specifier: link:./vendor/interceptor-plugin`、`version: link:vendor/interceptor-plugin`；
- `node_modules/tla-prelaunch-budget`：Junction，Target 为 profile 内副本，`realpath` 位于 profile 内。

## 4. pnpm 一致性检查的边界

本机 pnpm 为 `11.28.5`。尝试离线全量解析：

```text
pnpm --dir <profile> install --offline --ignore-scripts --frozen-lockfile --lockfile-only
```

结果 exit 1：`[ERR_PNPM_NO_OFFLINE_META] Failed to resolve @nanmicoder/dsh-agent-teams ...`。
离线镜像没有该包元数据，因此**不能**用这条命令声称 manifest/lock 全量一致；它也没有改写 lock。

改用结构校验（`tools/check-migration-links.mjs`）：manifest 与 lock 的 `specifier` 相同、
`version` 解析到同一 profile 内目标、Junction 真实路径与 manifest 一致、副本指纹与登记指纹一致、
活动配置中不残留旧路径文本。共 23 项检查，全部通过。
